## Purpose

定义技能节点参数、节点规则与引用关系的统一作者合同，使人工编辑、完整Document修改、复制保存和编译对同一技能产生一致结果。图拓扑继续由现有原生图拥有，节点业务数据只有一个来源，迁移不得留下旧配置补读或第二份可写图。

## ADDED Requirements

### Requirement: Skill节点参数必须只有一个正式来源

每个正式技能节点 MUST只保存一份业务参数。人工编辑、Document写回、导出和编译 MUST读写该参数；画布宿主、包格式对象和编译输入 MUST不得额外保存可独立修改的同义配置。节点/边identity、连接与图拓扑 MUST继续由现有正式原生图拥有，MUST不得建立另一份可写图集合。Macro接口和Blackboard声明 MUST保留各自唯一正式来源。

#### Scenario: 两种入口修改同一参数

- **WHEN** 作者在画布修改移动节点速度，随后导出并以Document修改同一速度
- **THEN** 画布、重新导出的Document和编译输入 MUST读取最后一次正式提交的同一数值
- **AND** MUST不存在另一份旧速度作为补读来源

#### Scenario: 重新打开已保存图

- **WHEN** 保存后重新加载技能图
- **THEN** 参数、节点identity、端点与Macro接口 MUST来自唯一正式资产
- **AND** MUST不通过合并两个可写图恢复内容

### Requirement: 节点定义必须完整覆盖所有正式作者能力

每个可编辑节点kind及其变体 MUST具有唯一正式定义，覆盖参数字段、默认值、类型与合法值、字段可见性、端口、引用及编译能力。创建目录 MUST只暴露完整可创建、可编辑、可导出、可校验和可编译的能力；覆盖范围 MUST包含已登记但当前演示资产未使用的节点与原生逻辑节点，不得只按演示图裁剪。

#### Scenario: 扩展节点字段

- **WHEN** 正式节点定义增加一个可写字段
- **THEN** 原生编辑与Document MUST使用同一字段身份、默认值和约束
- **AND** 缺少完整读写或编译合同的节点 MUST被拒绝进入可编辑目录

#### Scenario: 未在Corin使用的合法节点

- **WHEN** 作者创建正式目录中已登记而Corin未使用的节点
- **THEN** 该节点 MUST仍能通过相同的创建、保存、导出、校验和编译链

### Requirement: 所有作者入口必须具有一致字段能力

原生Inspector、创建菜单与Document MUST消费同一字段定义和写入规则。复杂字段 MUST提供对应typed编辑能力；可写字段不得只在Document可修改，也不得由UI自行接受超出合同的数值或引用。不同界面可以有不同排布，但权限、必填条件与合法值 MUST一致。

#### Scenario: 编辑按标签查询移除效果

- **WHEN** 作者把效果移除方式设为标签查询
- **THEN** 原生Inspector与Document MUST都能配置同一查询内容
- **AND** 切换选择方式后的字段可见性与必填条件 MUST由同一定义决定

#### Scenario: 提交非法参数

- **WHEN** UI或Document提交违反正式字段约束的值
- **THEN** 写入 MUST在部分修改正式数据前拒绝，并指出节点及字段

### Requirement: 节点端口必须由同一正式形状决定

节点kind、typed参数与正式动态接口 MUST唯一决定端口identity、类型、方向、容量和顺序。画布连接、Document端点校验和编译 MUST使用同一形状，MUST不从默认节点实例、已有连接或运行getter推定规则。重命名和布局变化 MUST不改变端口identity。

#### Scenario: 黑板节点切换访问方式

- **WHEN** 黑板节点由读取切换为写入
- **THEN** 画布与Document MUST得到相同的输入/输出形状
- **AND** 会使已有连接失效的变化 MUST明确拒绝或通过同一完整改线目标处理，不得静默丢线

#### Scenario: 修改Macro参数名称

- **WHEN** 作者仅修改Macro参数显示名
- **THEN** 接口、调用点和编译 MUST保持同一参数identity及原连接

### Requirement: 引用关系必须覆盖完整作者生命周期

正式引用合同 MUST表达调用槽、目标、目标角色、私有/共享所有权和稳定调用方身份。导出、闭包校验、事务owner收集、复制、删除回收、迁移与版本计算 MUST使用相同关系。新增一种引用后，所有消费者 MUST能看到同一目标，MUST不得各自维护节点类型与引用字段列表。

#### Scenario: 只由转移边引用条件图

- **WHEN** 条件图只被一条转移边引用而没有旧步骤引用
- **THEN** 该图 MUST进入导出、校验、保存和失败回滚的完整闭包

#### Scenario: 复制含私有条件和共享Macro的技能

- **WHEN** 作者复制包含私有条件图及共享Macro的技能
- **THEN** 副本 MUST拥有独立的私有条件图并重映射对应引用
- **AND** 共享Macro MUST仍指向原正式共享资产

#### Scenario: 删除仍被共享引用的内容

- **WHEN** 作者删除一个共享Macro调用点
- **THEN** 删除 MUST只修改该调用及可回收私有内容，不能删除其他调用仍使用的共享资产

### Requirement: 状态转移与组合步骤必须各有唯一配置

状态机转移的条件、优先级、中止策略和稳定顺序 MUST只属于对应转移边；状态机状态、入口和任意状态 MUST不再保存旧步骤转移数据。状态及入口转移输出 MUST允许多条转移，目标状态输入 MUST允许多个来源；已声明的其他端口容量不因此改变。普通组合流程 MUST保留自己的步骤与执行语义，不得被隐式改成状态转移。

同优先级转移 MUST使用显式、同来源下唯一的稳定顺序；保存、重命名或位置变化 MUST不改变选择次序。任意状态无条件转移 MUST继续非法，其余条件与调度业务遵循 `btsmtl-skill-transfer-connections`。

#### Scenario: 修改转移条件

- **WHEN** 作者在线上更换条件图
- **THEN** 导出、复制和编译 MUST立即以这条边的条件为准
- **AND** MUST不存在节点步骤上的第二份条件

#### Scenario: 多个并列转移同时满足

- **WHEN** 同一来源的多个同优先级转移同时满足条件
- **THEN** 运行 MUST按明确保存的顺序选择，重载后结果一致

### Requirement: 编译必须消费同一业务定义而保持现有运行链

Skill编译 MUST读取正式参数、端口、引用和拓扑，保持kind、源identity与调用路径映射。编译 MUST不通过构造旧作者节点、执行画布委托或另行推断字段规则解释技能。运行 MUST继续只消费现有Semantic IR/Program链生成的产物，不读取可变作者对象；编译需要的操作和端口映射 MUST不反向成为作者配置。

#### Scenario: 相同业务目标从不同入口提交

- **WHEN** 画布与Document分别提交相同的技能业务目标
- **THEN** 编译 MUST得到相同的业务参数、连接和引用语义
- **AND** SourceMap MUST能定位到对应正式节点、端口、边及调用位置

#### Scenario: 编辑器显示运行值

- **WHEN** 作者查看已编译技能的运行结果
- **THEN** 显示 MUST消费既有运行诊断，不重新执行作者节点

### Requirement: 画布布局不得污染作者语义版本

作者语义版本 MUST包含参数、执行顺序、端口、连接、引用及其业务依赖；位置、分组和视图状态 MUST只影响画布布局版本。Document整包hash MUST仍包含可编辑layout，但纯布局变化 MUST不改变技能语义版本或使同语义运行来源失配。Program状态布局版本 MUST与画布布局版本明确区分。

#### Scenario: 仅移动节点

- **WHEN** 作者仅移动节点或调整画布分组
- **THEN** Document包hash与画布布局版本可以变化，技能语义版本 MUST保持不变
- **AND** MUST不因此要求重新发布相同业务的Program

#### Scenario: 修改转移顺序

- **WHEN** 作者调整同优先级转移的明确执行顺序
- **THEN** 作者语义版本 MUST变化，不能被当成纯布局修改

### Requirement: 模型迁移必须完整替换旧来源

迁移 MUST按精确根列出参数、端口、引用、identity和顺序映射，在旧数据仍可读取时核对并封存来源。新旧配置冲突 MUST逐字段报告，未经裁决不得覆盖；迁移 MUST进入既有完整资产事务。正式目标成功后旧字段、旧补读、无消费者模型和一次性迁移入口 MUST删除，不得长期保留双读或双写。

#### Scenario: Step和Edge内容不同

- **WHEN** 同一转移的旧步骤和新边保存不同条件或调度字段
- **THEN** 迁移 MUST列出具体转移与差异并停止该资产的覆盖
- **AND** MUST不默认选择任一侧或用空值覆盖有效值

#### Scenario: 迁移保存失败

- **WHEN** 任一owner保存或反向导出失败
- **THEN** 唯一事务 MUST恢复已有资产及package，并清理仅本次创建的内容
- **AND** MUST保留失败证据且不得报告完成

#### Scenario: 迁移后再次读取

- **WHEN** 迁移后的精确根重新导出并进行无修改对账
- **THEN** 正式包 MUST无语义差异，校验与编译 MUST只消费新来源
- **AND** 正常入口 MUST不需要旧字段或迁移器才能工作
