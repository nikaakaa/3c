## Context

原 `remove-agent-authoring-use-native-csharp` 已归档。本次是其后续精简实施，动机及现行 spec 差异见 proposal。

当前 Attack 文件为 1,166,932 字节；已观察到 graph 变量名身份后缀、创建参数内图身份、外部资源路径/localFileId、入口内绝对 SourceCodePath。尚未逐字段统计体积，不能把总大小都归因于 GUID，也不承诺压缩比例。

## Goals / Non-Goals

目标是在同一正式 API 版本与外部输入下，用尽量少且可读的 C# 恢复作者内容及其正式关系。最小指不重复保存可推导数据，不指最少字符或最少代码行。

用户确认的目标形态是偏函数式的链式 builder：源码规模随节点、连接、Clip 数据段引用和作者配置数量增长，不随 Clip 时长、采样频率或派生字段数量增长。这里的“只保存作者编辑过的信息”指当前最终的显式配置与覆盖值，不是读取 Undo 历史或记录编辑过程；AI 和人工设置的正式配置采用同一规则。

不复制 YAML 字节、旧 C# 写法、任意编辑器缓存和操作历史。不新增 JSON、字段配置仓库、反向源码解析、同步模式、兼容入口、测试或验证任务。不改变已有正确的业务规则来适应导出器。

## Decisions

### D1：按重建用途逐字段裁剪

导出输入为明确根、生成 owner 范围及外部依赖；输出为正式创建调用和必需参数。领域适配沿已有正式元数据与 API 判断字段用途，不能另建一张与业务定义并行的字段真相表。

| 内容 | 输出规则 | 对作者的影响 |
| --- | --- | --- |
| 类型、业务配置、节点值、动态端口配置、Blackboard 声明、FSM 转移条件 | 保留非默认配置和有意义的显式覆盖；默认值、类型决定的固定端口和结构由正式 API 恢复 | 源码表达作者选择，不展开工厂内部实现 |
| Timeline 对 Clip 数据段的使用 | 保存精确源引用、源区间、时间轴位置及速度/混合等作者配置，不复制源 Clip 曲线或每 tick 数据 | 一个片段用一段创建表达式即可重建 |
| 独立作者曲线 | 保存作者关键帧、插值/切线及正式时间域；引用已有曲线时只保存源引用和覆盖 | 保持真实编辑结果，不把曲线烘焙成密集采样数组 |
| 拓扑、业务顺序、共享关系、owner、根绑定 | 保留；对象引用使用本次创建结果 | 循环和共享对象恢复，Profile/Definition 不悬空 |
| graph/node/edge/variable identity | 仅正式引用、稳定拓扑身份或 owner 关系需要时保留原值 | 需要跨重建识别的元素仍能定位 |
| 无引用、无稳定身份约束的内部 GUID | 不输出原值；由正式创建 API 分配并以返回对象连线 | 内部对象仍存在，但物理/无消费身份不保证与旧资产一致 |
| 外部资源 GUID/localFileId | 精确定位外部输入需要时保留；项目相对路径若为正式解析方式也可使用；不并列重复保存同一定位信息 | 子资源不误绑；不复制范围外素材 |
| 名称、节点位置及有意义的作者布局 | 每个节点输出一份位置，必要布局配置输出一次；不抄选中态、视口、重绘缓存等编辑器状态 | 恢复作者排版，数量随节点增长 |
| 变量名中的 GUID 后缀、非业务 GUID、诊断 hash、生成时间/过程信息、历史操作日志、可重算缓存 | 不输出 | 源码只描述当前目标内容 |
| 绝对 SourceCodePath、重复 EntryTypeName、调度 recipe | 移出创建数据，见 D3 | 源码可随项目迁移，不依赖开发者本机目录 |

未知字段不是可删字段。不能判断重建用途时定位字段并报告未支持，保留旧输出；实施时明确其正式用途后再决定写出或省略，不把未知值默认为零。默认值省略基于当前正式 API 的固定语义，不增加 fallback/default 配置；API 版本变化按正常源码迁移处理。

字段值等于默认值但“显式覆盖”本身会改变继承关系时，必须保留该覆盖意图；不能只做值相等判断。读取现有正式覆盖语义，不新增作者编辑标记库或第二份配置树。

### D2：GUID 根据消费者保留，不根据外观保留

对于 graph/node/edge，每一类身份要明确：谁读取、用于什么关系、创建完成后是否仍需旧值。正式 API 参数名叫 id、字段可序列化或字符串长得像 GUID，都不能单独证明必须记录旧值。

- 范围外正式消费者、owner 绑定或稳定编译引用需要精确旧身份：保留，不能仅因本图没有入引用就删。
- 范围内链接可由创建对象、端口和有序连接表达，且领域没有稳定身份要求：使用对象变量；新 id 由工厂分配。
- Edge 需要稳定身份才能挂载转移条件、owner 或其它正式引用：保留；否则输出端点、配置、顺序即可。多条相同端点的边仍分别创建，不按端点去重。
- 正式 API 强制旧 id 且没有自动分配语义时，先由该领域决定并补入正式创建职责。禁止传空串、伪造常量、反射绕过或导出器私建第二套身份系统。

业务取舍：全部保留身份有利于逐元素历史对应，但会把没有消费者的序列化身份变成源码负担；全部重分配最省表达，却会破坏正式引用。本次按消费者保留，代价是领域适配必须解释身份用途，不能统一正则删 GUID。

### D3：调度元数据与创建内容分离

创建类只保留正式执行合同与 C# 自身的类型声明，删除 `SourceCodePath`、重复 `EntryTypeName` 和仅用于调度的 `RecipeType` 实例属性。业务配置内真正用于角色/资源选择的类型标记不在此删除范围。

`source_code_path`、`entry_type_name`、`recipe_type` 仍可作为两工具请求/响应的调度信息，由现有生成服务解析。类型身份来自已编译类型；源码归属来自 Unity 当前编译/脚本关联；recipe 是请求的调度标识，其适用性由现有正式领域/目标规则判断，不复制进生成资产或源码属性。上下文按请求提供 Definition、输出范围及外部输入。

工具仍须确认精确源码与当前已编译入口关联，仍拒绝未编译或旧编译结果。若现有 Unity 编译接口不能提供需要的关联，由实现明确指出缺口；不得通过源码自报绝对路径或新增旁路注册文件掩盖。编译关联不属于资产源码的字段裁剪，不能趁迁移删掉这一业务安全条件。

业务取舍：源码自带调度字段使调用服务少做关联，但搬项目或移动源码就失效；放在工具请求与现有编译关联中使源码独立，代价是生成服务承担精确定位。不会为省几行源码新增 manifest、持久化注册表或第二套协议。

### D4：可读表达与语义等价

变量用业务名或 `graph1`、`node1`、`edge1` 等当前调用内短名，重名加序号，不含 GUID/hash 后缀。多次使用的同一外部资源先声明一次再引用。类型采用必要 using/别名减少重复全限定名称；不靠压成超长行或把大字段塞入字符串/二进制/JSON 达到表面缩小。

保留创建、配置、引用绑定、连接与根挂接阶段，环与共享引用处理不变。输出重建等价作者内容，不要求原 YAML、fileID、无消费身份、旧变量名或旧源码文本一致。必要身份只在需要的位置表达；不能在变量名、创建参数、诊断和注释里反复复制。

业务取舍：主要减少的是不该进入源码的派生内容和重复源数据，不只是缩短名称。保留真实作者关键帧，不复制源 Clip 的大数组或增加独立压缩格式；不凭未经统计的样本承诺固定 KB 上限。

### D5：Timeline 使用 Clip 数据段，不导出逐 tick 曲线

一个 Timeline 片段表达“使用哪个正式 Clip 的哪段数据、放在哪里、如何播放”。输入是精确 Clip/数据段引用、源起止区间和 Timeline 位置，以及作者设置的播放速度、混合、循环或其它正式覆盖；有默认值的配置无需重复写出。源时间域与 Timeline 时间域分别交给现有正式 API 处理，不混用二者，也不逐 tick 展开时间映射。

原 Clip 中已有的曲线、每 tick 采样、烘焙/分析缓存和运行编译结果不生成到创建源码。范围外源资源是重建输入；删除 Timeline 生成资产不删除它。源资源在明确生成范围内时只创建/引用一次其正式作者定义，后续片段引用该对象，不按每次使用复制其派生数据。

作者在 Timeline 上创建的独立曲线或覆盖曲线输出作者关键帧和完整插值语义，包括需要的切线、权重和时间域；只覆盖值与引用原曲线由领域正式语义决定。不把这些关键帧采样成固定 tick 数组，也不进行有损抽点。现有整组曲线修改和 owner 规则继续由正式 API 承担。

业务取舍：完整复制样本能冻结某一次采样结果，但会随时长和采样频率膨胀，并重复 Clip 的数据；引用数据段让源码短且由 Clip 统一维护，代价是重建依赖同一源资源内容及正式算法版本。若现有正式数据只剩样本、无法取得源数据段或作者关键帧，明确指出该领域缺口，不把样本冒充作者配置，也不建立第二份素材文件掩盖。

### D6：链式 builder 直接调用正式创建能力

输出按业务对象组织：创建节点后链式配置，Timeline 通过嵌套函数表达片段；连接引用创建结果。Builder 是正式领域创建 API 的薄表达层，参数语义、默认值、固定端口、合法性、owner、保存继续由正式模块负责。不新增持久化 AST、操作日志、第二份领域树或另一套执行器；“偏函数式”不要求引入不可变对象框架。

下例仅说明目标阅读形式，不声明已有这些方法；实际方法名和参数按正式领域概念收敛：

```csharp
var attack = graph.Node<Attack>("attack")
    .At(320, 160)
    .Damage(20)
    .Timeline(t => t
        .Clip(attackClip)
        .Range(0.2f, 0.8f)
        .At(0f)
        .Speed(1.2f));

graph.Connect(start, attack);
```

节点位置只在所属节点表达一次，Timeline 的 At 表达其自己的时间位置。固定创建细节藏在所属正式 API 内，不藏在新 DTO 中。循环和共享图仍允许先声明对象再连接，不能为追求一条链重复创建共享对象或改变业务顺序。

业务取舍：链式表达让作者直接阅读对象与配置关系；需要维护少量领域 builder 方法。逐字段底层赋值虽然直接，却把工厂细节暴露到每份源码。本次选择薄 builder，并随迁移删掉被替代的重复输出路径，不建立可选的第二输出模式。

## Risks / Trade-offs

- 将“未在当前图找到引用”误判为“没有消费者” → 以正式领域外部引用和 owner 合同为边界；不通过全项目猜测替代明确绑定。
- 默认值随 API 版本改变 → 重建承诺限定相同正式 API 版本；值有业务差异就写出。
- 源 Clip 内容改变会影响重建 → 重建输入明确包含该源内容；不为冻结派生样本而把它们写回 C#。
- 只删模板噪声，主导体积的重复配置未处理 → 实施逐字段按 D1 分类，改薄适配和表达，不先添加字段；不预报未经统计的节省比例。
- 生成类合同变化使旧生成源码不编译 → 同一迁移中修改正式入口及已采用的生成源码，不留双入口兼容。

## Migration Plan

1. 在各正式领域明确现有身份消费者和默认创建语义，改动冲突的现行正确业务须提出具体冲突。
2. Timeline 改为正式 Clip 数据段引用和作者覆盖输出，独立曲线使用作者关键帧；由正式模块恢复采样与派生内容。
3. 在正式领域创建 API 上收敛薄链式 builder，在现有公共导出上下文中收敛短变量名与资源复用；位置每节点一份。
4. 修改唯一正式生成入口及服务调度，移出生成类内路径/recipe/type 自报字段，保持当前编译关联要求。
5. 重新输出已采用的正式 C#，保留其文件和 meta；不为缩小源码删除正式素材或改写作者曲线。
6. 实施完成后同步当前 spec 和 skill 的状态说明。无手动验证、回放或证据归集任务，验收由用户完成。
