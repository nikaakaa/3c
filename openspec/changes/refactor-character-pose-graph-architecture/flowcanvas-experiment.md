# PoseGraph 原生 FlowCanvas 实验

更新：2026-09-08。状态：范围已确定，实验尚未实现。本轮先更新文档。

## 当前决定

先用 PoseGraph 验证 FlowCanvas 的原生节点编辑和运行求值，不只复用端口样式。后续 BTSMTL 技能图也可能采用同一基础，因此实验不得把通用图生命周期写死为 Pose 专用。技能图迁移不属于本轮实施范围，不能用 Pose 实验结论代替技能中断、Timeline 生命周期、固定步长和状态恢复的验证。

这是一项明确标注的独立实验，不是 Corin 的第二条正式运行路径。实验不得装入正式 Character Definition、GameplayLab composition、默认启动配置或正式构建产物；正式角色继续使用当前已装配链路。实验通过也不自动完成全量迁移或替换当前架构规范。

## 最小业务链

```text
Clip Player A ──┐
               ├─ Blend ── Output Pose → 实验角色动画
Clip Player B ──┘
                  ↑
                Weight
```

- 输入：明确选定的现有 AnimationClip A/B、实验 Animator、混合权重、帧编号和时间步长。
- 处理：原生 FlowCanvas 端口绑定与求值，Pose 节点调用动画业务模块；每个角色独立保存状态，同帧重复读取复用结果。
- 输出：实验角色的最终动画姿态，以及能够说明求值次数、播放时间、输出次数和生命周期的诊断结果。
- 本轮不包含：IK、完整动画状态机、Motion Matching、Linked Pose、Action Slot、技能图、网络、生产迁移和生产性能承诺。

## 图与运行职责

| 部分 | 实验采用的职责 | 不应出现的情况 |
|---|---|---|
| 图资产与节点 | 真实 FlowGraph／FlowNode，使用原生保存、复制和节点 UI | 旧 CharacterPoseCanvasNode 外面再包一层显示图 |
| 端口与连接 | 原生 typed Value 端口和 BinderConnection；Pose 约束由领域类型及校验提供 | 两份连线列表、默认类型转换掩盖 Pose 空间错误 |
| 角色更新 | 显式帧入口驱动图，明确启动、推进、停止和销毁 | 多个 Update 入口各自推进同一个角色 |
| 节点状态 | 每实例播放时间和本帧缓存，不写入共享作者资产 | 两个角色共享播放游标或混合历史 |
| 动画计算 | 节点调用输入输出明确的播放、混合与最终输出模块 | 节点内部偷偷构建旧 Pose 图并调用旧图执行器 |
| 编辑与观察 | 使用原生端口、连接状态、选择和 Undo；观察不得推进动画 | 查看端口数值或重绘造成第二次播放时间推进 |

实验主链必须为 `FlowCanvas 正式实验图 → Pose FlowNode → 动画业务模块 → 实验角色输出`。

不接受 `FlowCanvas 图 → 旧 Pose 图 → Program Image → 旧 Pose Executor` 作为本实验的成功结果。后者只能证明编辑器转换可行，不能证明 FlowCanvas Runtime 能承担 PoseGraph。

## 实施前需要核对的依赖

现有模块不能因为类名带有 Player／Blend 就直接判定可复用。逐项检查输入是否仍依赖旧 ProgramImage、operation index、内部执行页、根帧事务或旧 Scheduler：

1. 可以直接接收 Clip、时间、权重等业务输入的模块，列为直接复用。
2. 算法与旧调度耦合的模块，列明需要分离的职责；不得以新增包装类掩盖旧图执行依赖。
3. 由 FlowCanvas 接管的图连接和调度职责，列为未来正式迁移的删除项。
4. 无法在实验范围内解耦的部分，报告具体输入输出和取舍，不绕过现有系统修改正式角色。

FlowCanvas 当前 ValueInput/ValueOutput 使用 getter 求值，不能据此假定同一节点每帧只执行一次。缓存、播放状态推进与输出时机必须有明确所有者。托管委托调用也不能自动继承当前 Native／Job 链路的性能结论。

## 完成条件与证据

| 要回答的问题 | 所需证据 |
|---|---|
| 是否真实使用原生节点和运行连接 | 图的节点类型、端口类型、连接模型及实际运行调用链；没有旧图转换执行 |
| 作者能否正常编辑 | 创建、拖动、连线、改接、删除、复制粘贴、撤销、保存、重新打开的实际结果；不能只凭编译通过 |
| 混合是否影响动画 | Weight 为 0、1 和中间值时的角色输出；至少一个明确变化的动画通道 |
| 同帧多次读取是否安全 | 同一帧重复读取后播放时间不重复推进，计算和最终输出次数符合声明 |
| 多角色是否隔离 | 两个实验实例以不同时间／权重运行，状态和输出互不覆盖 |
| 生命周期是否完整 | 停止、重启、销毁后状态归属明确，Playable／运行图等资源正确释放 |
| 性能代价是什么 | 明确硬件、Editor／Player环境、实例数、样本量及采样开销；缺少同条件对照时只报告绝对结果 |

不新增单元测试或测试脚本。编译、运行和采样使用项目已有正式能力；没有可用的执行入口时必须先说明实际缺口，不用临时修复工具改正式资产。人工反馈可以作为交互证据，但不能代替运行计数、资产往返和性能结果。手动验收不写入 tasks.md。

最终交付必须列出：已复用的原生能力、仍需维护的领域代码、需解耦的旧模块、实际证据、未验证项和正式迁移的业务取舍。只有最小链路及上述必要正确性条件得到证据，才能标记实验闭环；未经测量的性能与未实施的完整 Pose／技能迁移保持未完成。

## 与现有规范的关系

- tasks 16.3、design 的 CanvasCore／FlowCanvas 取舍和拒绝项，以及本 change 的 Pose delta，原先禁止 FlowCanvas Flow／Value 进入正式 Pose 执行。
- current `openspec/specs/character-presentation-pose-graph/spec.md` 要求正式 Runtime 消费 Program Image、不得解释 authoring Graph；因此直接替换正式 Runtime 与现行要求冲突。
- 本次仅新增用户明确要求的独立实验范围。既有禁止项继续约束正式 Character 链路，不应被拿来宣称独立实验也禁止，更不能把实验例外扩展成生产切换许可。
- 若实验后决定正式采用 FlowCanvas Runtime，必须同时修改正式执行、Compiler／Build、Frame 生命周期、Document、Diagnostics 和迁移删除条款；不能只修改 UI 要求就切换角色。
- 本 change 的历史正文仍有 Document v4 称呼，而现行实现及技能合同为 v5。本轮不新增 v4 支持，也不把历史字样当成实验输入格式。
