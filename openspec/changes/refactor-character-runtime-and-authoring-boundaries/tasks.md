# 实施切片草案

当前阶段是规划。后续长任务先按 design 的“长任务排查与交付协议”覆盖 R1—R10 并给出方案；本清单只记录已知实施切片，不构成自动实施授权。全部保持未勾选，工作区已有代码不等于本 change 已交付。排查决定保留或转交的条目应修订清单并记录理由，不伪记为实施完成。

R1／R2 的已有提交、R8 的保留结论、R9 的证据与专项归属记录在 design，不复制成新的已完成任务。测试、手动验证、用户验收与采集运行不列为 tasks；实际修改仍按项目规则执行基本检查并如实报告。

## 1. 收口会话历史职责（R3）

- [ ] 1.1 完成 SimulationSessionHistory 对检查点集合、裁剪缓冲与历史分支的唯一持有，Host 只接入 runtime、roster 和已完成 Tick。
- [ ] 1.2 将捕获、精确恢复、目标 Tick 恢复和输入区间恢复统一接入 History，保持正式兼容性检查、失败回滚与原有状态交接，不复制会话暂停或 Active 状态。
- [ ] 1.3 完成新会话重置、runtime 绑定／分离及销毁调用迁移，删除 Host 中被替代的历史字段和旧实现，形成完整独立提交。

## 2. 收口动画采样职责（R4）

- [ ] 2.1 完成 AnimationSampler 对预览场景、采样实例、PlayableGraph、NativeArray 和临时 Clip 的统一生命周期管理。
- [ ] 2.2 让 Analyzer 从同一规范样本数组执行现有几何、特征与 Motion Data 构建，保持 Target／Motion Reference 的采样时刻、坐标空间、loop 及末端语义。
- [ ] 2.3 移除 Analyzer 内被替代的采样环境与重复辅助入口，保留唯一正式分析入口、既有数值算法及 artifact／曲线输出。

## 3. 整理Pose作者工作区（R5）

- [ ] 3.1 将 State／Alias 的领域数据创建交给现有 StateMachine mutation，窗口只传递 document、位置与选择并刷新页面；状态、子图、布局继续在同一 Undo 事务内。
- [ ] 3.2 由正式校验报告携带错误定位身份，统一作者检查与带 Rig 内容检查的输入模式，删除窗口和内部重复执行的同一能力／状态机校验。
- [ ] 3.3 收拢图、Profile 与其正式引用参数资源的保存操作，支持正式无 Profile 作者入口，移除 Tuning 模块内独立的保存协议。
- [ ] 3.4 将导航目录、图显示名、角色与规则 owner 查询移到只读作者目录职责，窗口保留选择、打开页面和导航历史。
- [ ] 3.5 删除已确认无消费者的 tuning 指纹字段、方法、分支及对应文件／meta，同时清理直接调用者。
- [ ] 3.6 删除只执行 Validate 的 Compile 入口、虚假编译成功提示和过时 Projection／Build 状态命名，更新 presenter 等直接消费者，保持实际采用状态来自正式 Session。

## 4. 清理旧作者依赖（R6）

以下删除范围由 design 规定的完整引用证据确定；存在正式消费者的对象保留或完整迁移，不以清空目录为目标。

- [ ] 4.1 清理已不需要的 TreeDesigner import，并同步正式 C# 作者代码导出模板，避免后续生成重新引入旧依赖。
- [ ] 4.2 删除已确认没有业务消费者的旧 Action／Equipment／Input／Motion 等节点簇与专属端口／包装，保留正式 Flow 节点仍使用的接口和业务值合同。
- [ ] 4.3 对清理范围内的反射发现、能力注册、序列化类型名、资产引用和 meta 完成同一职责迁移，删除旧位置，不保留别名或兼容入口。
- [ ] 4.4 按最终实际类型依赖更新 Character Runtime／Editor asmdef；仅在整个闭包不再需要时删除对应 TreeDesigner 包及程序集，仍保留的依赖在 design 说明消费者。

## 5. 按已有职责整理文件（R7）

- [ ] 5.1 将 TimelineRuntimePreparation 中既有 Preparation、Playback、Evaluator、缓冲与合同按责任归文件，保持类型与运行语义。
- [ ] 5.2 将 CharacterFootSwingMotionBuilder 中合同、诊断与算法按现有职责归文件，保持数值计算、字段布局和访问方式。
- [ ] 5.3 将 CharacterTimelineHost 同文件中的独立服务／合同归到对应现有职责文件，保持新 GraphBindings 与唯一播放状态，不增加转发模块。

## 6. 文档与迁移收尾（R10）

- [ ] 6.1 在正式规格同步阶段应用经审议的 Pose 整帧责任与 Workspace 行为增量，保留现有模块所有权、失败门槛和算法约束。
- [ ] 6.2 根据完整排查后的实际 Foot artifact／曲线／资源准备链修订已确认过时的规格条款；同步修订 proposal 的 capability 清单及对应 delta，不把未确定数据链写成现行事实。
- [ ] 6.3 更新 R1—R10 的最终状态、对应提交、保留理由、专项交接和证据限制，使 OpenSpec 总入口与一般文档不再维护两份不同完成清单。
