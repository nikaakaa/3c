## Purpose

规定客户端、服务端及正式依赖在游戏运行阶段的托管内存分配、存储所有权、容量与跨帧消费边界，使零托管分配目标不以破坏玩法状态、回滚快照、网络可靠性、表现提交或诊断完整性为代价，并明确生命周期分配和未覆盖路径的报告规则。

## ADDED Requirements

### Requirement: 正式运行阶段必须零托管分配

正式准备完成后，在已声明内容与容量内的输入、逻辑步、重放、世界求解、动画、相机、AI、消息收发、运行UI及所选正式诊断模式 MUST 为0托管分配。首次技能/效果使用、首次达到合法并发峰值和后台运行线程 MUST 包含在此约束内。启动、显式加载、退出和离线导出 MUST 分开记录，不得以改阶段名称掩盖Active期间分配。

#### Scenario: 首次技能切换

- **WHEN** Active角色首次使用已安装技能并创建合法数量的表现请求
- **THEN** 所需工作和结果存储 MUST 已由正式owner准备，过程不得托管分配或热点扩容
- **AND** MUST 保持原技能、动画和事件语义

#### Scenario: 后台网络运行

- **WHEN** 客户端或服务端线程处理正常收发及重传
- **THEN** 项目及正式依赖调用的托管分配 MUST 纳入对应进程证据
- **AND** MUST 不以主线程为0或将工作移到后台宣称全路径达标

### Requirement: 复用存储必须保持事务与消费者寿命

Pending、Committed、回滚历史、异步发送和表现观察 MUST 保持各自有效寿命。借用结果不得逃逸其合同边界，跨帧或异步结果 MUST 在所有消费者完成后才可复用。租用失效、重复归还或代次不符 MUST 明确拒绝，不能读取其它角色或下一帧数据。

#### Scenario: 下一步开始但网络尚未发送完成

- **WHEN** 上一步结果仍由网络或历史持有
- **THEN** 下一步 MUST 使用其它已准备可用存储，不能覆盖旧结果
- **AND** 容量不足 MUST 按正式准入或失败合同处理

#### Scenario: 世界求解后事务丢弃

- **WHEN** 本步未能正式提交
- **THEN** MUST 丢弃本步候选且保持已提交状态和历史不变
- **AND** MUST 不为减少复制提前改写共享Committed状态

### Requirement: 容量必须正式声明并有界失败

容量 MUST 由正式内容布局推导或所属领域明确配置，准备阶段验证所需范围。运行超限 MUST 在安全边界拒绝请求、背压或失败，不热点扩容、不部分提交、不静默丢弃权威事件。MUST 不使用无限全局池或缺配置默认值绕过。

#### Scenario: 合法峰值

- **WHEN** 同时活动播放、效果、碰撞候选或消息达到已声明合法上限
- **THEN** MUST 在准备容量内完成且不分配
- **AND** 报告 MUST 给出容量与实际峰值占用

#### Scenario: 内容超出容量

- **WHEN** 安装内容已证明超过所属领域可用容量
- **THEN** 正式准备 MUST 失败并定位内容及容量来源
- **AND** MUST 不缩减能力、丢事件或降级另一配置继续运行

### Requirement: 内存治理不得改变既有业务表达和协议

治理 MUST 保持值端口类型、连接、求值顺序、状态寿命、Timeline时钟/Marker、Pose原生执行、IK公式和网络canonical数据。替换分配型接口 MUST 同步所有正式消费者并删除旧热点入口，不保留双运行链。第三方正式调用的缺口 MUST 单列并提供证据，不以项目自有代码无new替代整体结论。

#### Scenario: 更换返回列表的接口

- **WHEN** 独立结果改为借用或租用存储
- **THEN** 所有消费者 MUST 明确新的有效期并一起迁移
- **AND** MUST 不把复用的可变列表冒充原先独立不可变结果

#### Scenario: 求值优化改变执行次数

- **WHEN** 消除分配被提议同时引入缓存或短路改变
- **THEN** MUST 将该语义变化明确为独立决定，不混入存储归位宣称等价
- **AND** 当前GC治理不得据此删除未证明完整去向的能力
