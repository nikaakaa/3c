一.介绍：
主要使用的是第三人称模板

技术方案来自于 GDC2016 刺客信条的预测 Foot IK

同时参考了其他大佬的文章

同时在 AI 的帮助下（疯狂提问）选择了一些方法（现在看起来也有些蠢）

总之，这是一个比较 trick 比较个人的技术方案



二.过程：
1.曲线：
行走相位 Phase ：使用曲线来反映在时间上 当前行走的状态，比如抬腿，落地，摆动等情况

Phase 的曲线可以有多种形式，比如（0，1）的过程，0 是刚抬腿的时候，1 是落地的时候，总之这是一个将具体的动作过程抽象成一个 float 值的过程，用于后面的计算过程。

这个曲线可以自己手加，也可以用 modifier 来批量添加

参考油管的视频，给动画加上曲线：

UE4 Character's Feet Prediction (Using Anim Curves) UE4Tuts For You#UE4tuts#UE4

2.预测：
预测的过程很简单，就是 终点 = 起点 + 速度*时间

然后使用这个终点来进行 trace：






这里提前将时间（也就是曲线值）存入到了结构体内，所以这里直接拿结构体的值了






使用 sphere trace 不用 line 的原因是 line 比较细，在台阶边缘处等情况可能会 trace 到地面上，站不稳或者会滑下台阶出现跳变的情况

然后在落地的时候进行 debug 绘制起点终点等



至于这里使用的 Get Actor Location 而不是使用 Foot 骨骼的位置，是因为 Foot 骨骼会被动画影响，可能会出现预测点回弹的情况

3.盆骨：
我们可以通过终点-起点的方式来判断上下坡，然后得到盆骨的移动过程（上升或者下降）

在这个过程中就会遇到这个 bug：






可以看到在跨越两个台阶的时候，起点和终点中间是没有高度差的，但是胶囊体会下沉，导致我们的 Mesh 也会下沉，就出现了这种情况；这个时候就要让我们的 Mesh 抬升盆骨，减去胶囊体下沉的高度，补足这个情况。

在尝试多种方法无果之后：

参考了 shadow 大佬的锁定方法，直接 Set Mesh 的高度在起点处了，起码这么做之后看起来是对的。






但是后面计算 Pelvis Offset 的时候并没有继续按照 shadow 大佬的思路来做 Additive，而是回归了传统的 IK 方案：也就是在 control rig 里面直接 MIN 运算左右脚了，最后得到的结果也是对的。



4.路径：
如果只是做到了上面的步骤，我们能勉强出现预测的效果，但是这个效果并不好，特别是上下台阶的时候会穿模，上下楼梯的时候会抖动，跨越台阶的时候也会穿模（特别严重），仅仅只能做到人物“提前”上抬和下沉了。

GDC 里面的做法是在 pelvis 的高度上自身为起点，预测点为终点，绘制一个胶囊体，然后从上往下 Sweep，返回得到的所有点位，然后给这些点位进行 sort，组成一个新的数组，让 Foot 能够跟随这些数组进行移动，就不会进行穿模了，也就是使用 Foot Path 重构了移动路径。



计算 Foot Path：

这里使用的是 双端交叉式迭代生成路径，以起点和终点作为起始点，向前/向后进行 trace，前后交叉进行，等到循环结束或者条件不满足时就结束，再将得到的结果按顺序存储起来。

可以参考 左加右 大佬 和 修勾 大佬的文章，他们都有讲（然后把他们讲的东西丢给AI），就能得到一个比较准确的解决方法了。






采样 Foot Pah：

光有信息是不够的，接下来是如何采样这个 Foot Path；

这里需要计算一个 Foot Rate，在空间上反映我们的行走情况：

我这里使用的是计算投影的方法，当前位置在这一段路程（起点到终点）中所占比就是我们这一步行走的百分比




然后用这个值去映射到 Foot Path 中，比如当前位于这一步的 20% 左右路程，然后就会返回 Foot Path 中 20% 所对应的 Location.Z，我们只要 Z 值，因为我们的脚是实时运动的，我们只需要知道在这条路径上脚需要抬多高就行了

然后我们发现这样也不能完全避免穿模问题，因为有时候会 trace 到边缘部分，这里很容易出现穿模，于是我们需要再对我们现在的双脚进行一次实时的 Trace，比较 Z 值的高度，取高的那个即可。



5.切换：
其实到这里整个过程就已经差不多完成了，结果也看起来比较正常。

但是也会有一些奇怪的 bug 出现：

比如转向的时候会 trace 非常多次，站立的时候也同属于“落地”的情况，也会疯狂 trace






所以需要在预测 IK 方案和传统 IK 方案之间进行切换（比如速度，比如时间，比如急转弯的判定）





6.效果与问题：
最终效果：



其实这只是一版技术实现，距离可落地的目标还很远，需要优化的地方也很多，只是看起来最基础的大体没啥问题

比如：在 Trace 到台阶边缘的时候由于误差会出现跳变（可能 trace 到台阶上，更新后在台阶下了）

预测点的 trace 没有进行约束，有时候会打到墙上或者比较高的物体上，即使那个地方我们上不去
