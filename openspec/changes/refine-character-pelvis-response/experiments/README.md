## 已形成的算法经验

1. 最终世界骨盆不是Correction本身。Root移动、原动画与加权Correction必须分别计算；266的Correction下降50毫米，不等于世界骨盆下降50毫米。
2. 统一到一个模块只消除了重复职责，没有取消硬边界的最终决定权。目标先Clamp、Spring后再按同一硬区间限制，是当前算法；边界本帧降低时，弹簧不能保证拦住突然下压。
3. 腿长不是只看脚高。上界为ankleY−hipY＋sqrt(radius²−horizontalDistance²)。322／466即使脚底高度没变，Root／Hip上升和横距增加也会吃掉可达空间。
4. 正式Rig两段腿长与同帧实际骨长差不足0.4微米，不支持靠把Rig腿“补长”修下陷。20毫米余量确实有额外下压贡献，但10毫米真实实验没有通过全身质量。
5. Stage3后最严重420窗由未锁定的Swing脚收紧Reach；它是合法有效Foot目标的腿长约束，不是支撑权重为0就自动不参与。不能偷偷关闭Swing Goal或改低权重来让骨盆看起来正常。
6. 414时目标已为0而输出还约+107毫米；419约+42毫米，420被硬压至−1.674毫米。不是每个窗口都缺“提前知道该下降”的信息，也不能把所有问题只归为Spring太慢。
7. 985支撑权重尚非零时仍采用完整约+446毫米请求；986资格退出转回0。资格开关、目标幅度和响应历史要分别审查，不能凭权重小直接推导应同比缩小目标。
8. Foot目标合法性独立于Correction大小。0.1毫米Goal门已被实测否决，不得为了减小骨盆冲突重新引入。
9. 中心贴面不等于Heel／Toe都贴面，接触平面负距也不等于已证明穿入有限Collider。中心位置、朝向、实体表面是三种观察。
10. Solved Knee实际步、相对动画的extra步、跨版本点差、最终Physical Knee不是同一指标。当前包没有最后一种；旧翻侧移到下一帧也必须保留，不能只删掉原峰。
11. 总分及窄Landing腿域不能替代全包骨盆／膝盖。局部公式正确、输入Proof匹配、FBBIK到Goal准确都不等于整体效果合格。
12. ZZZ支持已闭合的结构和数学，不支持任意字段借名。f不是Approach，274不是PlantBlend，writer W不能统一叫PositionWeight；共同190／194不是每脚第二弹簧。新闭合的powf只补普通响应核，不补完整目标、腿约束及最终求解政策。
