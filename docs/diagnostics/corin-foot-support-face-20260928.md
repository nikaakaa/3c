# 台阶边缘支撑查询修改

## 已交付的行为

撤销 `2f59a39f8` 的末级期限加速，恢复原响应速度。支撑资格改在现有 `CharacterFootPlacementWorldQueryBackend` 内处理：

1. 原 SphereCast 继续收集附近碰撞体，容量、半径和 LayerMask 不变。
2. 对每个候选碰撞体，沿同一个请求中心的向下方向执行该 Collider 的 Raycast，确认标定点正下方是否存在实际表面。
3. 未覆盖该支撑线的候选剔除；坡度过滤使用确认后的表面法线，不再使用球侧擦棱边的法线。
4. 通过确认的表面按实际射线距离排序，点、法线、Collider 身份来自同一次确认结果。

这是必经的候选确认，查询失败不会恢复使用球形擦边结果。当前脚跟、脚尖、未来落脚点、当前接触验证都使用同一个 `ResolveSupportCandidates` 实现。地面路径 CapsuleCast、Swing 目标、接触残差、FinalIK 和骨盆未修改。

确认线从原查询起点开始，长度为球心行程加球半径，覆盖原扫掠底端；没有额外搜索更远地面。使用现有 RaycastHit 缓冲区、Ray 值类型和 Collider.Raycast；不新增运行数组、集合或闭包。

## 检测范围的准确含义

本次使用已有 Heel/Toe 的正式标定点和预测落脚中心确认踏面。它不是完整鞋网格的面积接触模拟，也没有把历史五点偏移直接拿来代替当前标定点。真实脚跟在高踏面范围内时，高踏面仍能通过确认；只有球侧面碰到旁边碰撞体、该碰撞体不覆盖标定点正下方时，才被剔除。

这与历史“优先低面”“优先较平的低候选”不同：不按高度偏好排除候选，而是要求该面实际覆盖支撑点。窄物体只有擦到球、没有覆盖 Heel/Toe 或落脚中心时，不会成为支撑；完整鞋掌部分承重仍超出当前双点合同，不能声称已覆盖全部鞋底接触情形。

## 作者显示与采样

- 原五点支撑编辑页面改为 `Support Query`，显示实际 Heel/Toe 球形扫掠和绿色支撑确认线。
- 作者选择 Pose Graph 使用的正式 Foot Placement Profile；半径及上下范围只读该 Profile，没有另建预览参数或默认数值。
- 运行 Module 与编辑器共用 `CharacterFootCurrentSupportProbeRequest.Create` 生成请求，显示和运行范围一致。
- 已移除未参与当前查询的五点编辑手柄和误导性 Ray 说明。旧校准资产没有重写；其五点序列化数据仍属于现有校准/几何身份合同，本次未迁移该身份，也未重烘焙动画。
- 正式 full 采样增加 `Coverage.SearchHitCount`、`SupportHitCount`、`OutsideSupportRayCount`、`SteepSurfaceCount`，并记录 `SupportMaximumDistance`。下一次采集可区分未搜到碰撞体、搜到了但不覆盖支撑点、真实面坡度不符。

## 用户手测重点

沿原问题台阶下行，让脚跟落在高台阶边前方几厘米处，再稍微前后移动。观察支撑是否仍被旁侧高台阶反复托起，以及真正站在高踏面时是否仍能正常支撑。普通平地、普通下坡应保持原响应节奏。若仍有抖动，使用新增 Coverage 字段和原有 SurfaceIdentity、目标/解算位置区分查询切换与后续交接，不继续盲目修改响应速度。
