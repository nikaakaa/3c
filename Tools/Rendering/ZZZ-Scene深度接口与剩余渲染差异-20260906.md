# Scene 深度接口与剩余渲染差异

## 当前状态

这一步是 URP 接入修正，不是改原材质配色，也不是完整还原声明。Shader 新通道已通过原材质重建中的变体编译；Scene 实际视口的最终开关对照尚未完成。

新增验收入口加载时，项目其它 AgentAuthoring 文件出现 `AgentAIDocumentMutationModule`、`AgentBlackboardDocumentMutationModule`、`AgentGraphDocumentMutationModule` 缺失错误，阻止 Editor 程序集更新。此任务未修改那些文件，也未清理用户 Console 来掩盖错误。

后续只读对账发现多个磁盘脚本有合法 GUID，但在 AssetDatabase 中仍为 Unknown；已经通过正式 ImportAsset 登记现有文件，没有修改 Authoring 逻辑。新的编译仍被 `AgentGraphReferenceMutationHandler` 中可空类型返回、未赋值局部变量及类型名作为值等错误阻塞。不能继续把这些错误归为 Shader 或未导入文件。

`20260906-scene-depth-controlled/` 的手动资产 A/B 已恢复全部 Shader 标签，但相机在 On/Off/Restored 之间发生位移，所以这一组是无效验收记录，不能使用其中的大像素差量证明修复。

## 已核对的事实

- Scene 和 Game 都使用 `URP-HighFidelity` 默认 Renderer；恢复 Feature 已启用。
- Scene 为 Textured、场景光照开启、透视 60°；Game 相机透视 35°，两者视口高度也不同。
- Scene 相机离屏描边开关对照有 3421 像素变化，证明程序执行；离屏图不能替代真实 Scene 视口验收。
- 实际 Scene 视口曾出现网格穿过角色、轮廓较弱；用户在过程中移动过 Scene 相机，不跨不同视角做像素差量验收。

## 确认的深度接入缺口

安装版 URP 14.0.12 的 `UniversalRenderer.cs`：

1. 约 684 行：Scene、Gizmos 会要求深度预通道。
2. 当前 SSAO 的 Source=1，需要深度/法线预通道。
3. `DepthOnlyPass` 只选择 `DepthOnly` 标签；`DepthNormalOnlyPass` 选择 `DepthNormals` / `DepthNormalsOnly`。
4. 约 1329 行：Scene 最后把内部 `m_DepthTexture` 复制到相机目标，供编辑器使用。

恢复 Shader 原先只有 `CharDepthOnly` 标签，没有上述 URP 标签，因此不向这个预通道提供角色几何。原 Feature 后来画入自己的角色缓冲，并不自动补回 URP 内部预通道。该缺口需要修，但尚未用真实视口 A/B 证明它解释了全部 Scene/Game 差异。

另一个排除项：本机 CopyDepthPass 已按 destination.graphicsFormat=None 自动选择 `_OUTPUT_DEPTH`；不能把默认构造参数 copyToDepth=false 当成本轮唯一原因。

## 实现切片

- Body/Face 的原 `CharDepthOnly` 程序保留，调度标签接为 URP `DepthOnly`。
- Body/Face/Eye 增加 `DepthNormalsOnly` 接口：复用各自原顶点和片元裁剪程序，额外输出 URP 所需的几何世界法线。它不是原游戏新增 Pass，也不是社区光照替代。
- Eye 没有独立原深度程序，复用原 Eye 顶点/片元程序，深度通道关闭颜色写入。
- 新增 `CharacterPreparePass`，在 URP 深度预通道前准备同一份实体数据和材质全局输入；原颜色缓冲阶段不再重复准备。
- 生成器同步维护这些接口，不修改原 VS/PS 指令、纹理、光照参数或线宽。
- 深度法线使用几何法线，不是原角色后级 GBuffer 的材质法线。未声明两种缓冲编码相同。

编译中出现过缺少 Common.hlsl 类型定义、系统生成输入顺序错误，均已修正。之后原材质重建成功日志位于当前 Editor.log 的后续记录；旧异常日志不能当成新一轮编译仍失败，也不能据此清空整个 Console。

`CorinRestoredRenderingAudit` 已增加相机、Scene 模式、Renderer 和真实视口开关对照入口；恢复开关使用 finally，不保存场景。最新真实视口入口尚因上述其它编译错误无法加载，不能记为验收完成。

## 离完整原版仍差什么

| 层级 | 已有 | 仍需闭合 |
| --- | --- | --- |
| 原资源/程序 | 原模型、材质、纹理、主要 Shader 阶段及计算程序 | 不等于当前运行条件完整 |
| 深度和模板 | 原描边可绘制；本轮补 URP 深度接口 | Scene 真视口验收、原 stencil 144 与材质 128 的优先级、扩边深度边缘覆盖 |
| 角色光照供数 | 208→128 字节布局与原 Compute | 当前固定环境光、空的灯光混合列表、GI/阴影资源未完整接入；不能仅把关闭开关改成 1 |
| 坐标输入 | 已有角色/头骨数据和 dump 对象 | 原头骨朝向、中点和渐变参数的生产方式与项目逐项对应 |
| 缓冲合同 | 四路颜色/法线缓冲可工作 | 原格式 48/4/75/75 与项目 RGBA16F 的编码和精度对账 |
| 后处理 | 原合成、角色 LUT 与部分场景参数 | 逐阶段状态、不同场景供数、避免把旧缓存参数当所有场景常量 |
| 效果验收 | 有项目截图与用户游戏参考 | 对齐视角/光照后检查发灰、头发高光、衣服层次、眼睛、阴影和动态稳定性 |

旧 ZZZ 快照中的 GI/主光阴影也曾为关闭状态。因此“项目有关闭项”只证明供数链尚不完整，不能单独证明发灰的根因，更不能据此宣称开启 GI 就完成还原。
