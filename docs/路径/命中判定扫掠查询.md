# 命中判定扫掠查询

业务方提供逻辑轨迹样本、形状、请求来源、几何过滤和目标数据。判定模块连接同一轨迹身份的前后样本，调用原生碰撞后端，返回全部相交目标。当前能力只覆盖几何判定，攻击开始 / 结束、阵营、次数、间隔、伤害、`AttackLanded`、Effect 与表现接线由业务方负责。

## 调用链

```text
业务方正式轨迹采样和 typed 参数准备
  -> SweepDataGenerator.WriteTrack
  -> SweepQuery<T>
  -> FixedSweepQueryBackend / UnitySweepQueryBackend.SweepAll
  -> SweepResultBuffer<T>.Candidates
  -> 业务方消费或丢弃
  -> SweepResultBuffer<T>.Release
```

源码根为 `3cDemo/Client/3C_Client/Assets/GameScripts/Main/Runtime/Simulation`。

| 入口 | 职责 |
| --- | --- |
| `Core/Collision/SweepQueryContracts.cs` | typed 位姿、形状、轨迹、请求、过滤、来源、后端能力和候选合同 |
| `Core/Collision/SweepDataGenerator.cs` | 将一条轨迹按其逻辑样本时间连接成段，写入调用方存储 |
| `Core/Collision/SweepResultBuffer.cs` | 合并重复目标、保留最早接触、稳定排序、失败与借用释放 |
| `Core/Fixed/Collision/FixedSweepQueryBackend.cs` | 定点凸体准备、MPR 平移、GJK 连续旋转，消费只读目标批次 |
| `Unity/Collision/UnitySweepQueryBackend.cs` | 已绑定 Physics Scene 的 NonAlloc Overlap / Cast，映射正式目标身份 |

## 输入准备

- 调用方从唯一正式内容降低为 `SweepShape<FixedScalar>` 或 `SweepShape<Float32Scalar>`，预创建后端、样本 / 段数组和结果缓冲。模块没有另一份可写 AttackProperty、轨迹作者配置或采样时钟。
- `Sphere` 使用半径；`Capsule` 的 `HalfLength` 是局部 Y 轴上两球心间内线段长度的一半，总高度为 `2 * (HalfLength + Radius)`；`Box` 使用半尺寸。尺寸由正式内容准备确认。
- `ConvexHull` 接收有体积的凸体顶点，准备时复制并以顶点均值重新定心，局部中心偏移保留在正式查询姿态中。输入顶点的整体凸包就是查询体。
- `ConvexMesh` 接收预先准备的凸部件及局部姿态。部件引用形状表中更早的条目，准备时展平嵌套部件。查询逐部件求交后按目标合并，凹处保留；不会把整份凹 Mesh 的顶点变成一个凸包。当前不自动凸分解，不解释任意三角网格或变形 Mesh。
- 样本位姿是查询形状作者原点或 Mesh 根原点的逻辑世界位姿。技能相对 Actor 的偏移和朝向由业务采样方在原逻辑运动链中处理；凸包重新定心与 Mesh 部件偏移由准备后的形状表达保留。模块不读取表现骨骼或 Actor Transform 补输入。
- 一条 `SweepTrack` 保留稳定点 / 形状索引、运动模型与 `SamplingSource`。每次 `WriteTrack` 只连接该轨迹自己的样本。多个刀身点分别调用，写入段数组的不同区间；不同动作实例使用不同请求来源。
- 样本时间严格递增，根位置在段内线性插值。`RigidRotation` 使用归一化端点四元数之间的最短、恒角速度旋转弧，凸部件的局部偏移随根旋转。单个样本生成同位姿、同时间的零运动段；空样本写入零段。旋转超过半圈或往返运动须由业务方提供中间逻辑样本，不能仅凭相同端点重建。
- `SweepQuerySource` 保留请求、Actor、Tick、Action Context、内容、节点、播放与调用身份，结果存储保留这份来源。调用方拥有来源与逻辑时段的一致性。
- `SweepTargetIdentity.TargetId` 是调用方分配的稳定目标身份，`ShapeId` 区分目标子形状。目标身份不为零；`ExcludedTargetId=0` 表示无排除目标。阵营和命中接受不属于几何过滤。

## 两种后端

| 后端 | 输入与真实能力 | 不支持 |
| --- | --- | --- |
| Fixed | 预创建球 / 胶囊 / Box / 凸包 / 凸部件 Mesh；`StationaryPose`、`LinearTranslation`、`RigidRotation` 目标批次；双方平移与旋转使用同一逻辑时段 | 任意三角网格、变形 Mesh、自动凸分解、Fan 自动替代、Unity Collider 输入 |
| Unity | 正式绑定的 `PhysicsScene`、Collider 到稳定目标的映射；球 / 胶囊 / Box NonAlloc Cast 和起始 Overlap；目标为 `ScenePose` | 双方时段连续运动、任意形状连续旋转、Fixed 求交 |

Fixed 的 `SweepTarget<T>` 提供形状索引、Layer、Trigger 与起止逻辑样本。`StationaryPose` 使用开始位姿，开始时间必须等于请求的 `TargetPoseTime`；运动目标的时段必须覆盖查询段。`LinearTranslation` 保持朝向；`RigidRotation` 同时插值根位置与最短旋转弧。球的朝向不影响几何。

Unity 在准备时确认 Collider 属于绑定 Physics Scene，使用原场景的原生几何，`Targets` 传空 span。所有查询过滤后可能返回的 Collider 必须有正式映射；缺映射返回 `UnmappedCollider` 与 `FailureNativeObjectId`。`TargetPoseTime` 由场景时间 owner 提供，模块不刷新或推进场景。Layer 与 Trigger 由原生 API 过滤，目标排除在身份映射后处理。

Fixed 后端版本锁定 `9237daa68c3014fd7c2e93c6a99326ba5248d60b/mpr-gjk-angular-query-v2`，依赖和许可位于 `Assets/Plugins/BepuQueries`。只在适配器内部使用原生 Fix64，项目 Q32.32 Raw 直接转换；原生数学舍入、溢出和容差与项目数学不相同，不要求 Unity / Fixed 输出相同数值。Box 原生 margin 设为零，保留作者尺寸。

固定朝向的平移走 MPR；明确声明旋转的请求走 GJK 最近点与保守推进，不按固定密度补做 Overlap。推进使用极值点分离平面的间距和双方平移、角速度与外接半径的闭合速度界。GJK 与推进各最多 64 次，耗尽返回 `NativeIterationLimit`。旋转接触收敛距离为 `0.0001`，同时保留原生 GJK 的数值容差；该阈值不代表全域 TOI 误差界。初始相交没有唯一接触点，接触字段仍按实际可用性发布。

## 结果与生命周期

`SweepAll` 返回状态。只有 `Complete` 可以读取 `Candidates`；失败时保留失败段、目标和原生对象身份，不能将失败当作空命中。每次请求按 TargetId 合并，时间有效时保留最早接触，平时按时间、目标、子形状、轨迹、形状和段索引排序。没有可比较时间时 `TimesComparable=false`，按稳定身份交付。没有跨 Tick 去重或命中记录。

初始相交由原生相交求值处理，候选只标记时间，不伪造唯一接触点或法线；运动接触保留实际可用字段。法线统一为目标朝向查询形状。`Time` 是调用方逻辑时间，`Fraction` 是当前段的接触比例；`TargetPoseTime` 区分静态场景时点与双方运动接触时点。接触点与法线必须依据 `Fields` 消费。`SourcePartIndex`、`TargetPartIndex` 标识展平后的凸部件，并参与同时间候选的稳定排序。

调用方准备一个或多个 `SweepResultBuffer<T>`，每份直到消费或丢弃后才 `Release`。前一结果未释放时重用会明确报错；多个 Step 或 Replay 结果同时存活时使用不同预分配存储。结果 span 只在该借用期间有效。Unity 原生查询区额外预留一个槽，返回数超过声明容量即失败；候选容量不足同样失败，不截断成功。

没有查询请求时由调用方跳过调用。模块无 MonoBehaviour、Update、Tick、Pipeline Pass、Snapshot participant、Scene 世界重建或跨 Actor 状态写入。

## 检查与限制

运行证据见[命中判定查询核对](../测试/命中判定查询核对20261001.md)。当前 Editor 中 Fixed 数据生成 / 查询 / 释放及 Unity 查询 / 释放各连续 1000 次测得 `0 B` 托管分配。该局部检查不能证明完整攻击、跨平台确定性、回滚接线或 Player 总体 GC。

以后接入 Quantum 3 时复用样本、形状、时间、身份和结果语义，在对应数值 / 场景适配中显式声明真实能力。当前不安装 Q3，也不提供空适配或迁移保证。

## 下一步正式技能接线

用户本轮要求尽快验证判定后的技能逻辑，范围同时包含受击 / 硬直 / 打断、格挡 / 招架 / 反击、震动 / 停帧；这些消费者须沿同一正式命中结果接入。

当前仍没有生产调用方执行 `SweepAll`。需要由技能 Timeline 的正式攻击事件提供攻击实例、内容身份、有效时段与逻辑轨迹；判定后由攻击实例 owner 执行阵营、次数、间隔与目标接受规则，并经现有 `GameplayResult` / typed `SimulationIngress` 路由到目标 Actor 的 Evaluate。技能、效果和表现消费已提交的同一结果，不能从表现骨骼、另一 Actor mutable state 或额外 MonoBehaviour Tick 补一条运行路径。

扫掠代码与局部数值检查已完成；上述技能业务生产、接受与消费接线尚未完成。2026-10-01 后续代码修改时目标 Editor MCP 无会话，用户选择先完成代码、稍后连接，因此这批旋转扩展尚未经目标 Editor 编译和技能资产发布。
