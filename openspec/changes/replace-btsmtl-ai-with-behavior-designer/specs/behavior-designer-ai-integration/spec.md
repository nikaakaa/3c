## Purpose

定义项目使用现成行为树编辑和运行能力控制角色的正式边界：作者只维护一份行为内容，项目通过已提交观察、角色输入和动作结果接入插件，同时保持会话版本、输入所有权、调试和资源发布的一致性。

## ADDED Requirements

### Requirement: 游戏AI必须以插件原生行为作为唯一作者与执行来源

系统 MUST使用已选定行为树插件的原生图、子树、变量、控制节点执行和图调试。角色 AI 绑定 MUST引用同一份正式插件行为内容，不保存自研图正文、AI Program 镜像或双写资产。插件行为 MUST不被转换到另一套项目自研行为树解释器。

#### Scenario: 作者调整追击和攻击顺序

- **WHEN** 作者在插件图中修改一个角色的行为分支并发布新内容
- **THEN** 新会话 MUST直接采用该插件行为版本
- **AND** MUST不要求生成自研 AI 图或 AI Program

#### Scenario: 旧AI配置仍可达

- **WHEN** 正式角色或产品仍引用被移除的 AI 图、Definition 或 generated AI Program
- **THEN** 配置或构建校验 MUST明确拒绝该引用
- **AND** MUST不转换成兼容对象或回退旧执行器

### Requirement: 插件任务必须只通过正式角色观察和输入影响玩法

项目提供给作者的游戏任务 MUST读取所属会话的冻结观察，并通过受控角色输入目录产生移动、朝向、目标与离散请求。任务 MUST不直接写角色 Transform、Animator、Body、Action、技能、伤害或表现状态。输入字段 MUST使用稳定目录身份与匹配类型；未声明的能力 MUST在运行前拒绝。

#### Scenario: 配置接近目标

- **WHEN** 作者配置候选目标、停止距离及正式移动输入绑定
- **THEN** 任务 MUST根据逻辑观察输出角色移动输入
- **AND** 角色 MUST通过同一正式运动与世界求解链移动

#### Scenario: 行为包含直接移动角色的任务

- **WHEN** 正式角色行为闭包包含直接改写 Transform 或其它未授予玩法输出的任务
- **THEN** 正式配置校验 MUST拒绝该行为并定位任务
- **AND** MUST不以插件内置任务身份豁免角色写入边界

### Requirement: 请求提交与动作结果必须可以按原始身份关联

一次任务激活 MUST最多产生一次相同离散请求，并记录正式请求身份。后续等待 MUST区分请求排队、过期、准入拒绝、动作开始、完成与中断，读取正式 Input/Action 所有者发布的只读结果。插件成功状态 MUST明确表达提交成功或动作完成，MUST不以动画播放时间猜测动作终态，不保存第二套 Action 生命周期。

#### Scenario: 攻击尚在缓冲中

- **WHEN** 请求已提交但正式角色尚未接受该请求
- **THEN** 等待动作结果的任务 MUST继续等待或按明确的正式拒绝/过期结果结束
- **AND** MUST不因提交函数返回成功就宣布技能完成

#### Scenario: 等待中的动作被打断

- **WHEN** 正式 Action 结果表明该请求对应的释放已中断
- **THEN** 任务 MUST将该身份的中断结果映射为自己的结束状态
- **AND** MUST不创建新的释放或重发原攻击请求

### Requirement: 任务生命周期回调不得隐式取得角色取消权

插件任务结束、条件打断、图停止或资源恢复回调 MUST只处理任务自身状态和资源。角色取消/替换意图 MUST通过角色目录中明确存在的请求能力表达，并由唯一 Action 服务裁决。角色没有对应能力时 MUST拒绝该任务绑定。

#### Scenario: 插件停止调用任务结束回调

- **WHEN** 停止图或恢复插件数据触发任务结束回调
- **THEN** 系统 MUST不因此自动取消正在执行的角色技能
- **AND** 只有明确生成并进入正式输入的取消/替换请求才能影响角色

### Requirement: 同一输入批次必须由一个正式调度所有者推进插件

系统 MUST在 Source 的批量准备阶段，向需要决策的 Actor 提供同一版本观察，完成整批插件决策与输出校验后再交付角色输入。每个新输入 Tick 的插件推进 MUST唯一；同 Tick 的输入读取、重发、等待或重演 MUST不再次推进。自动逐帧更新与显式批量更新 MUST不重复执行同一批行为。

#### Scenario: 多个敌人同时生成输入

- **WHEN** 一个会话的多个 Bot 需要输入 Tick T
- **THEN** 它们 MUST完成本端批量准备后才允许角色模拟消费 T 的输入
- **AND** 输入结果 MUST不取决于逐 Actor 调用整组更新的次数

#### Scenario: 等待网络输入期间重复读取T

- **WHEN** 同一 Tick 的本端输入已冻结而会话暂未前进
- **THEN** Source MUST返回原输入
- **AND** BT、随机选择和请求捕获序号 MUST不因重复读取而再次推进

### Requirement: 行为内容与任务版本必须在会话采用边界锁定

正式内容发布 MUST记录行为身份、子树依赖内容版本、任务/插件版本、角色输入目录与输入所有权。运行会话 MUST使用启动时锁定的内容；图参数/连接更新、新任务代码和新的玩法 ABI MUST分别通过对应正式发布流程在新会话采用。插件即时编辑 MUST不被宣称为已完成正式内容发布或存活状态无损迁移。

#### Scenario: 图使用尚未安装的游戏任务

- **WHEN** 行为资源引用运行产品未提供的任务或角色能力
- **THEN** 会话准备 MUST失败并定位版本/能力缺口
- **AND** MUST不跳过节点或装载另一版本的行为替代

#### Scenario: 作者修改运行中的图用于调试

- **WHEN** 作者使用插件运行编辑能力改变行为
- **THEN** 本次调试 MUST不被作为原锁定内容的正式等价证据
- **AND** 正式内容采用与可对比运行 MUST通过匹配版本的新会话完成

### Requirement: 项目诊断必须关联决策输入与角色结果

图节点与变量观察 MUST使用插件原生调试。项目诊断 MUST提供行为身份、生产端、ActorId、观察 Tick、输入 Tick、请求身份、输入冻结/重发/消费及正式动作结果关联，MUST不伪造旧 AIProgram operation 或复制另一套图运行状态仓库。

#### Scenario: 排查敌人攻击未执行

- **WHEN** 作者查看某次攻击请求
- **THEN** MUST能区分未生产、已冻结待消费、缓冲中、准入拒绝和已释放后的结束结果
- **AND** 图调试与项目输入结果 MUST能通过该 Actor 和请求身份关联
