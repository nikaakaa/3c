## Why

Agent 阅读和修改整份 C# 创建源码时，会反复处理资源路径、分散配置和底层调用。需要优化工具输出的组织和写盘方式，使 Agent 通过短入口定位到少量相关文件并准确修改；这不是正式领域模型或运行链重构。

## What Changes

- 明确本变更只属于两个显式 Agent authoring 工具的输出、文件管理和诊断层，不迁入正式领域规则、业务模板、曲线处理、运行绑定或算法。
- **BREAKING** 清除 Agent 中手写成员清单、具体业务类型分支和默认常量，改为消费核心共享作者合同的正式描述与操作。核心在已有合同内增删字段、调整默认值、扩展同类节点时，Agent 不同步改模板或分支；不把旧适配器换目录冒充唯一来源。
- 先删除机械 emission 阶段包装调用、无用别名与全对象共享状态，集中同一对象创建和配置，再按修改边界组织短入口与少量阶段文件；私有小条件/Timeline 不单独拆。
- 私有对象使用局部变量，仅暴露跨文件连接真正需要的结果；每文件只写实际所需 using，不新增全局导入配置。
- 复用已有类型化 builder/正式 API，省略已知默认表达和固定结构，保持外部引用与必要身份；普通 C# 辅助函数只组织调用，不推断攻击阶段、命中/连段规则或新增通用业务模板。
- 保留已实现的唯一入口、多文件比较与明确范围清理，但不以文件数或单文件变小证明压缩；按同范围总文本、入口与局部修改上下文评估实际收益。完整导出仍不解析旧源码。
- 响应列出入口、文件与变更结果，错误定位根、局部对象、字段和对应文件；执行阶段只复用已有正式事务/保存能力，减少工具重复调用。
- 同步 Agent skill，正式领域知识通过当前 spec/API 引用，不复制进工具说明作为第二套规则。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `character-csharp-authoring`：明确 Agent 工具边界、多文件输出、稳定组织、相同内容不写盘及局部错误定位。

## Impact

仅影响现有 CodeGeneration 工具的输出上下文、文件写入、结果/诊断、薄适配中的调用表达和 Agent skill。已有正式 builder、生成执行入口与业务创建 API 保留，不修改 Graph/FSM/Timeline/Pose/Motion/Camera 的数据定义、默认规则、资源所有权、编译或运行算法。

现行 spec 对照：

| 现行要求 | 本次关系 |
| --- | --- |
| 完整读取正式资产、不解析旧 C# | 保留；完整计算输出文件集，不做双向源码合并 |
| 公共机制只拥有输出上下文等少数职责 | 补入工具自身的文件组织/写入和诊断，明确不拥有业务模板或规则 |
| 链式 builder 直接调用正式能力 | 保留并收窄解释：薄调用表达，不要求新建正式领域业务方法 |
| 结果返回代码文件、失败保留原文件 | 扩展为文件集与入口，完整表达失败时保持整组旧输出；写盘异常如实报告 |
| 默认值、源数据段、身份和共享资源规则 | 直接消费已有定义，不增加对应领域的 delta 或实施任务 |
| 现行“薄适配”仍容许手写每种节点的成员发射与默认比较 | 收窄为核心正式描述驱动，Agent 仅拥有通用表达；只读正式实例或调用正式 API 不再足以声明唯一来源 |
| 现行 spec 允许入口按原 emission 阶段逐项调用局部方法，skill 描述跨局部对象放执行状态 | 修订为只保留正式业务依赖；禁止机械拆出每步包装和全对象共享状态，私有内容合回局部 |

此前讨论“封装攻击阶段函数”和“集中事务”的建议，仅在现有正式 API 已提供相应能力时复用；不在本次新增 Attack 模板、领域事务或领域默认值目录。缺失能力定位为正式 API 缺口，不通过工具补一套实现。旧变更已归档，本次为新后续变更，不改写历史。用户在规划完成后已明确授权绑定实现任务执行，具体范围见 design。
