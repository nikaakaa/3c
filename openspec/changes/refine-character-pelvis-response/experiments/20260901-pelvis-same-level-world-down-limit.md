# 同平面双脚骨盆世界下降限速

## 结论

保留提交`68dde5c0c`作为针对性小步。它把固定Record中“双脚最终位置同平面但世界骨盆单帧下降超过1厘米”从7/19降到1/19；唯一剩余记录为10.00011毫米的Float32边界。Foot七维总分与全部既有质量Target没有回归。

这一步只解决同平面阶段的突然下沉，不宣称全局骨盆大步、动画过渡或膝盖问题已经解决。

## 原因

基线包`20260901-124439-709-612f6a6bcf684b33a2cab209cfc7b81b`的19个同平面连续窗中有7个下降超过1厘米。7个窗口都没有负的共同脚高请求；它们在支撑资格丢失后进入Releasing，骨盆目标回到0，同时Root和原动画骨盆继续下移。最终世界骨盆因此把动画／Root下降与骨盆修正回落叠加起来。

双脚同平面只说明脚的目标高度接近，不会自动阻止骨盆响应回零，也不会抵消动画和Root的世界位移。

## 单一变量

当左右正式Foot目标都为Ready、位置权重大于0，且目标Sole沿ComponentUp的高度差不超过1厘米时：

- 保留原骨盆目标、3Hz响应、Foot、Reach观察、脚锁和IK；
- 在唯一骨盆响应完成积分后，将最终Goal的世界向下速度限制为0.6米每秒；
- 将受限后的输出和速度写回同一份骨盆响应历史，不增加第二响应器或旁路Goal。

新增facts74／diagnosis43只发布并复算目标高度差、上一／请求／受限世界Goal、限速预算和实际介入，不改变七维评分。
