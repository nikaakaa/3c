# 可琳原描边：接入、证据与剩余边界

本轮补上项目漏掉的原描边调度和输入。实际相机开关对照确认描边生效，当前错误日志为 0。**这不等于整体效果已与游戏一致，也不等于原游戏所有 stencil 分支已复刻。**

## 原程序证据

- GameAssembly SHA-256：`4cba5d52c5fbfd478d2a9ec217075f82216780d56ad1bd1e85e4f724dcce30b4`。
- UnityPlayer SHA-256：`66493677ce2739e188c41634230c3a35e5f584c4575650949d0a53b5785c6c44`。
- `829` 是既有离线缓存，不是本轮活体读取，也不是与 0905 物理快照同一帧。

`GameAssembly+1EB66460` 的 ShaderTagIds 静态构造读取字符串、调用 `5408C98` 槽并保存整数 ID。用实际字符串和 ID 对账 UnityPlayer 的绘制函数；Shader.PropertyToID 属于另一张表，不能混用。

`UnityPlayer+945FE0` 中可定位的顺序：主体/脸部 → 描边 → 头发投影 → 脸部阴影重绘。描边分支还受 native state `+FA` 控制；本轮不猜其业务名，也不声称旧缓存当帧必然走了该分支。

身体 VS24/PS48 和脸部 VS12/PS44 都使用恢复的原程序，两个 PS 均输出四个 MRT，因此接入角色 GBuffer，不能直接在最终相机颜色上叠黑壳。脸部 PS44 另含条件 LUT 分支，保留原程序；其逐次配置与后级处理仍需核对。

`DrawOutlineObjectsPass` 的名字本身不足以指认角色几何描边。本轮结论取自实际标签及 native draw，不取自相似名字。

## 项目改动

唯一链路：`CorinOutlineSource.json → CorinRestoredMaterialImporter → CorinRestoredOutlineParameters → CorinRestoredRenderProfile.ApplyGlobals → CharacterBufferPass → 原四路缓冲 → 已有合成/后处理`。

| 输入 | 旧快照原值 | 项目处理 |
| --- | --- | --- |
| `_CharStyleParams` | (0, 1, 1, 0) | 正式 Profile 发布 |
| `_PostOutlineTint` | (0.721568644, 0.694117665, 0.768627524, 1) | 不手调黑色 |
| `_BloomThreshold` | (0.449999988, 3, 0.5, 100) | 原描边亮度标记输入 |
| `_AlphaBlendAlphaParams` | (-1, 1, 0, 0) | 原脸部描边 alpha 输入 |
| `_GlobalMipBias` | -1 | 共享采样输入，不冒称只影响描边 |
| `_NonJitteredProjMatrix` | 与旧相机相关 | 使用当前相机 GPU 投影，不冻结旧矩阵 |

没有修改原 VS/PS 指令、贴图、材质线宽、GI、主光强度或 LUT 色调。原 VS 还读取 Tangent、TEXCOORD1 和 COLOR：Color.r 参与线宽，Color.g 参与深度偏移。当前主体、脸部、头发和武器均有 Normal/Tangent/Color/TexCoord1；通道存在不等于导入前后逐顶点完全一致。

## 必须保留的差异

1. **Stencil 标记**：`UnityPlayer+947E10` 在描边前发布 `_CharacterStencil=144`、ReadMask=128、WriteMask=255、Comp=8、Pass=2；主体准备 `9471C0` 发布 stencil=128。当前恢复材质保存 128，恢复 Shader 将其声明为材质属性。本轮接通调度及 ReadMask，但尚未闭合“原生全局值 → 原材质/当前材质优先级 → 实际 stencil 写入”。不能把所有材质直接改成 144，那会改变主体和投影链。
2. **原扩边顶点数据**：通道存在已证；导入前后逐顶点值和平滑法线编码误差尚未量化。
3. **场景条件**：GI、主光阴影条件、头骨轴/中点生产、四路 RT 格式与场景调色仍是独立问题。本轮不调亮角色来掩盖它们。
