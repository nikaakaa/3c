## Context

本次是 Agent 使用的 C# authoring 工具优化，承接用户已确认的最小输出、链式 builder 和分目录/文件建议。正式领域是工具的输入和被调用者，不是本次需要重构的对象。当前仅更新规划与 skill，不修改代码或生成产物。

2026-09-14 修订：已实现的多文件版曾在本任务统计中显示 Attack 为 21 个文件、254,719 字节，入口 819 行；此前单文件样本为 161,208 字节。文件变小并不等于总量减少或理解更简单。本次明确纠正机械分阶段调用与全局执行状态带来的输出膨胀，先减包装和追踪关系，最后再分文件；本轮只修改文档，不把待修订内容写成已完成。

## Goals / Non-Goals

目标是同时减少重复源码和 Agent 修改时需要追踪的关系，让同一正式资产通过现有 API 正确重建。以同一导出范围的总文本、入口内容及一次局部修改涉及的文件衡量结果，不能只展示单文件行数下降。分文件不是固定数量目标，不应因包装、共享状态和重复文件头导致明显膨胀；必要新增文本说明实际用途，不靠丢数据压缩。

不新增领域字段表、默认值库、业务模板、攻击/连段规则、节点类型、曲线所有权、编译器、运行数据、资源处理或事务框架。不恢复旧 Agent/Document 协议，不做 watcher、源码解析/回写、自动同步、通用图模式识别、增量补丁协议或源码 Undo。

## Decisions

### D1：Agent 工具与正式领域的边界

| Agent 工具负责 | 只消费正式能力，不接管 |
| --- | --- |
| 文件路径、函数划分、变量命名、using、类型化调用文本 | 对象类型、字段、端口、默认值、身份用途和 owner |
| 当前输出调用内的对象/资源变量复用 | 共享资源的真实归属、资源加载与合法性 |
| 完整输出文件集、内容比较、归属范围内清理 | 正式资产创建、mutation、Undo、保存、编译与运行 |
| 将正式错误附上业务对象位置和输出文件 | 非法连接、窗口、曲线、状态等业务判定 |

薄适配可以决定“这个已有正式操作怎么写成 C#”，不能决定“攻击阶段应该包含哪些节点”。源码辅助函数只是普通 C# 调用组织，不保存中间领域树、不改变规则，也不成为独立运行入口。生成代码仍调用现有正式 API；缺能力明确报错，不为了完成压缩任务修改领域模型。

### D1.1：核心领域定义唯一，Agent 不随常规业务变更维护

正式资产实例提供当前值，核心领域已有共享作者合同/元数据提供可用类型、成员、默认/覆盖语义、端口、引用及创建/配置操作。Agent 通过稳定的正式描述接口读取这些内容，只负责通用 C# 值表达、命名、文件组织和写入。不是要求把所有业务改成一个万能结构，而是每个领域保持自己的唯一正式定义，工具统一消费其公开合同。

禁止在 Agent 侧维护具体节点/Clip 的成员清单、默认常量、合法组合、owner 判断或按具体业务类型逐个配置的 switch/if。已发现的 `motion.Priority != 100`、CurveId 默认字符串、按每种节点列举字段等属于待清理重复知识；调用正式 API 本身不能证明定义唯一。字符串、数值、枚举等通用 C# 语法分支可以保留，不能混入 Motion/Attack/Camera 等业务判断。

正式默认值和配置差异必须由核心领域共享合同提供，Agent 不抄一份，也不凭默认构造/零值猜测。字段和操作的描述必须来自领域已有定义或对该定义的派生投影，不能另加手工维护的 Agent 字段表。需要补充公开描述能力时归核心共享作者合同，UI 和其它正式作者入口仍可使用；不是把现有 Agent switch 换目录、改名后称为核心层，也不把 C# 排版/文件管理搬入核心。

| 核心变化 | 对 Agent 的要求 |
| --- | --- |
| 通过现有正式合同新增/删除成员、调整默认值或新增同类节点 | 当前领域编译可用后，工具从正式描述自动读取；不修改 Agent 分支或模板列表 |
| 修改合法性、owner、端口或创建规则 | 继续调用正式操作，核心结果直接生效；Agent 不复制判定 |
| 核心内部实现重构，公开合同不变 | Agent 不变 |
| 正式描述协议破坏性变更，或新增通用输出尚不能表达的值种类 | 可能需要一次公共协议/通用编码接续，明确报错，不做兼容双读或猜测 |

这里保证的是常规领域变化不需要同步维护 Agent，不承诺所有破坏性 API 变化都零修改。正式对象字段改名时生成文本可以随描述改变；工具代码不因此新增专用分支。仍然只有显式 export_code 才更新 C#，领域变化不会后台自动生成源码。

本次文档将消除重复领域知识列为独立待办，而非已经完成。现有曲线 descriptor.CreateDefaultCurve 等真正消费核心定义的正确路径保留；逐类型发射与硬编码默认值改为消费核心正式描述。缺少足够描述时列出具体类型/成员/操作缺口，不以已完成压缩掩盖定义仍有两份。

### D2：保留与收窄此前优化清单

| 项目 | 工具层做法 | 取舍 |
| --- | --- | --- |
| 曲线数据段与外部对象 | 输出已有正式源引用和使用配置，外部对象不展开 | 源码依赖明确资源；不重新定义曲线或共享所有权 |
| 默认值、固定端口、派生内容 | 按现有正式创建语义省略重复表达，显式覆盖有业务意义则保留 | 不维护 Agent 默认值表；不支持的省略仍完整表达或报告 |
| 身份 | 按已有正式消费者要求保留，变量名不携带 GUID | 不新增身份分配或稳定 ID 算法 |
| 资源 | 私有就近、共享声明一次，使用类型化业务名 | 不建立跨技能资源注册中心或复制素材 |
| 链式 builder | 复用已正确的正式创建入口，集中同一对象的调用 | 不创建领域 DSL、万能字段字典或第二执行器 |
| 重复搭建步骤 | 已有正式创建函数可直接调用；其它只拆普通组织函数 | 不在 Agent 内新增 CreateAttackStage 等业务模板，不自动猜相似图 |
| 节点位置 | 每节点表达一次，省略视口和选中态 | 保留作者布局，不扩成编辑器状态备份 |
| 集中保存 | 工具去掉自己重复发起的保存/刷新，消费已有事务边界 | 不绕过正式 mutation 或发明批处理事务 |

### D3：先收敛局部调用，再按修改边界分文件

一个明确导出根使用一个专属生成目录。先合并同一局部对象的创建、配置、私有条件和 Timeline，删除仅用于拆分输出步骤的 BuildCreate…/BuildConfigure… 包装函数和无用别名，再决定文件边界。输出器内部可以继续收集创建/配置/连接依赖，但不能把内部 emission 阶段机械转录成几百个入口调用。

局部文件以正式对象已有的状态/子图/阶段维护边界划分，不新增业务 Stage 或从名称猜运行含义。默认形态是短入口加少量阶段文件；阶段私有的小条件与 Timeline 合回阶段，真正共享、独立维护或明显过大的内容才拆出，不固定生成 Conditions/Timelines/Stages 三套目录。

示意：

```text
Attack/
├── Attack.cs
├── Attack1.cs
├── Attack2.cs
└── Attack3.cs
```

入口仍是同一个正式 Execute 合同，只组合局部构建结果、共享资源、跨局部连接和完成操作，不罗列每个节点的底层调度。阶段文件通过普通 C# 方法/partial 组织局部调用，不新增执行入口或业务模板。一个节点创建后保留其具体类型，将位置和有效参数就近配置，减少反复 cast、查找与别名；不能改动正式 API 来满足某种短写法。

私有节点和资源留在局部变量中，不把全部对象放入 GenerationState 再到处传递。只有跨文件连接确实需要的对象通过最小类型化参数/返回结果暴露；这只是本次调用结果，不成为可序列化领域模型或全对象镜像。共享资源在入口或确有必要的资源文件中解析一次，不为每个文件复制资源头。

需要跨局部循环时先创建必要的边界对象、再连接；不能为删包装破坏合法依赖。若拆分导致大量对象跨边界传递，优先合并该局部文件，而不是继续扩大全局共享状态。正式业务顺序、owner 和共享对象唯一性保持，优化的是工具组织造成的顺序约束，不删除正式创建所必需的顺序。

文件是否值得拆，以一次修改需要阅读和同时维护的内容判断；一个连贯文件优于多个互相跳转的碎片，不按固定行数强拆。

### D4：稳定名称与可定位输出

函数、文件和变量优先采用正式对象已有可读名称；重名仅局部消歧，不因另一个阶段增删而重新编号所有文件。合法 C# 名称转换由输出工具负责；必要身份仍只放在正式调用需要处，不额外造 GUID 文件名或持久化映射协议。

输出顺序按正式业务顺序及已知依赖确定。不能为了漂亮排序改变转移、轨道、端口顺序。根入口本身充当导航，不额外生成一份重复业务说明书或字段目录。

每个文件只输出其中实际需要的 using 与必要别名，不复制全套命名空间列表；计算所需类型来自本次输出表达，不解析旧源码。保留 C# 必需的 namespace/类声明，不通过 global using、隐藏全局别名配置或超长压行来省文本。减少文件碎片本身也是减少重复声明的方式。

默认参数、默认曲线和固定结构只有与正式默认语义完整一致时才省略，包括实际影响结果的关键帧插值、覆盖状态等；不将外形相似的曲线当作默认，也不建立 Agent 默认值表。显式非默认作者信息继续完整表达。

### D5：完整导出、按文件写差异

先从正式资产计算完整新文件集，在完整表达成功前不写目标文件。之后比较实际文本，相同则保持文件内容和时间戳，新增/修改只写对应文件；正常修改保留已有 meta。此比较只用于写盘，不解析旧代码、不推断手写结构、不建立资产增量同步。

沿现有输出路径请求定位唯一入口，并明确其专属生成目录为工具管理范围。该范围只允许本次生成文件，手写扩展放范围外并经明确普通代码引用；不能把已有混合目录直接认定为可删除范围。首次迁移旧单文件输出时只处理明确采用的路径，目录归属不明则报告，不扫项目猜旧文件。

在已明确归属的目录内，删除本轮输出不再包含的生成文件及其对应 meta，保持目录干净。现有文件被手改也仍遵守显式 export 的覆盖语义，不自动合并；需要永久保留的手写内容必须在范围外。没有内容变化时不触发工具主动刷新或编译。

文件写盘失败返回受影响文件及是否已写入，不能报告整组完成。无法表达正式内容导致的失败必须在写盘前发生，并保留整组旧源码；不为此引入通用多文件事务框架。下一次显式完整导出仍按同一范围重新生成。

### D6：多文件入口与诊断

generate_assets 仍执行一个已编译入口；局部文件只是该入口的 C# 编译依赖。现有源码与当前编译关联要求必须覆盖参与入口的辅助文件，不能因入口文件未变就执行旧的辅助实现；不另建编译缓存、加载器或持久化源码图。

导出响应给出精确入口和生成/修改/未变/删除文件；错误包含根、局部对象、字段/操作和文件位置，包装正式诊断而不复制业务检查。可在当前输出调用内维护定位信息，不生成长期 source-map 数据库。AI 可先读入口，再打开错误或修改涉及的局部文件。

正式创建期间，仅去掉工具层自己重复的保存/刷新调用，继续使用现有正式上下文完成；如现有 API 每步保存无法避免，记录所属 API 的具体限制，本次不改领域事务。生成成功只表示对应资产创建与保存结果，不附带领域运行、构建或验收承诺。

## Risks / Trade-offs

- 多文件使阅读更局部，但也增加引用关系 → 一个入口、按真实边界拆分、跨局部连接集中，不新增中间模型。
- 稳定文件名遇到同名对象 → 局部消歧，不依赖全局遍历序号或新身份系统。
- 自动清理误删手写文件 → 只管理明确的专属生成范围；不自动接管混合目录。
- 函数封装变成业务模板 → 仅调用已存在正式 API，组织函数不定义业务默认值或隐藏新节点结构。
- 只检查入口忽略辅助文件编译状态 → 复用当前编译关联覆盖完整入口依赖，不执行旧结果。

## Migration Plan

已有逐文件比较、归属清理、唯一入口及诊断能力保持。后续修订顺序为：合并机械包装调用 → 局部变量化、缩小跨文件结果 → 集中类型化对象配置并省略确定默认表达 → 按修改边界合并小条件/Timeline → 裁剪各文件 using → 重新生成并清理退役输出布局。仅改 Agent 输出器及生成表达，不迁入正式领域规则。

正常交付说明列出相同范围的总源码量、入口大小及典型阶段修改涉及的文件；不能只用分文件数量证明压缩效果。不添加独立测试、验证或统计框架，也不以报告流程卡住实现。
