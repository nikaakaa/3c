# 可琳头部受光轴对账

> 历史取证记录：保存当时现场与验证边界。当前工具与数据入口见[Rendering README](../../README.md)和[渲染数据总览](../../CorinRenderData/README.md)。

## 结论

原 `NapRenderEntity.UpdateBoneTransformsForFrame` 在普通 Transform 路径中以头骨 localToWorld 矩阵乘本地 `(0,1,0)`，归一化后写 `headBoneForward`。项目此前用 `face.forward`，即骨骼旋转的本地 Z 轴，属于明确的轴对应错误。

本轮只将 `CorinRestoredRenderEntity.FaceForward` 改为：

```csharp
face.localToWorldMatrix.MultiplyVector(Vector3.up).normalized
```

保留完整矩阵和归一化，未改头骨 Transform、Face shader 的 worldToLocal 矩阵、贴图、灯光速率、颜色或材质参数。新的方向仍由唯一 `PrepareInput.FaceForward` 进入原 Compute。

**修正轴不等于已证明它是全身发灰的原因；实际画面和 GPU 输出影响需要单独验收。**

## P0：静态调用与字段

同版本 GameAssembly SHA-256：`4cba5d52c5fbfd478d2a9ec217075f82216780d56ad1bd1e85e4f724dcce30b4`。

| 位置 | 事实 |
| --- | --- |
| 类型 27220，+70 | `HeadBone: Transform` |
| 类型 27220，+D8 | `headBoneForward: Vector3` |
| 1C9820E2 / 1C982157 | 从同一实体读取 HeadBone |
| 1C982224 → 槽 540C080 | 调用该 Transform 的 localToWorldMatrix getter |
| 1EA1DC70 | 元数据命名为 `Transform.get_localToWorldMatrix_Injected`，跳转到 540C080 槽 |
| 1C982292–1C982304 | 用 536312C 开始的三浮点常量乘矩阵的前三列 |
| 1C9810F0–1C98112C | 求模并归一化；过小分支采用零向量 |
| 1C981311 / 1C981318 | 写回实体 +D8/+E0 |

另一路先把矩阵存入实体 +E4，再进入 1C981087 的同一 `(0,1,0)` 运算，不改变方向定义。

Vector3 类型 5300 的 `upVector`：metadata_offset=10732 (`0x29EC`)，storage_flags=2。对应静态位置 `0x5360740+0x29EC=0x536312C`。829 离线字节：`000000000000803f00000000`，精确值 `(0,1,0)`。不是凭函数名猜测。

## P1：现有可琳快照与项目输入

0905 物理快照 `D:/ZZZ_Dump/output/ZZZ_20260905_101643.raw`，CR3=`0x62DF6A000`，只按已知地址读取少量字节，不读取活体。

确认的可琳实体 `0x7005F028640`：

- HeadBone=`0x70058A31D40`。
- vectorGetters(+B0)=0，transformProvider(+B8)=0，+2CC=0。快照保存的选择条件指向普通 Transform 路径，不是 getter/provider/job 路径。
- headBoneForward=(-0.266504079,-0.270336688,-0.925145149)。这是游戏当时的世界方向，不与项目当前不同姿势的世界方向直接比数值。
- +E4 矩阵缓存全零不能被拿来代替该普通路径的即时 getter 结果；代码明确会把 getter 矩阵保存在栈中计算。
