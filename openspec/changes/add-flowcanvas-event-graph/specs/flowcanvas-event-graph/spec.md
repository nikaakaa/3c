## Purpose

定义以事件为入口、由原生可视化节点完成计算、判断、变量读写与操作调用的通用事件图能力。各业务系统提供自己的事件、数据和生命周期，实例独立运行，共享作者与节点机制，不要求所有系统进入一张全局图。

## ADDED Requirements

### Requirement: 事件图必须复用原生作者和执行语义

系统 MUST允许作者使用原生画布、事件、执行连接、变量、计算、条件和 Macro 构建事件逻辑。事件图 MUST直接采用已准入原生节点的执行语义，不要求作者把同一逻辑另行编译为项目专用事件程序，不在不支持时切换另一执行方式。

#### Scenario: 作者连接条件和赋值

- **WHEN** 作者连接更新事件、条件分支和变量赋值
- **THEN** 事件发生时 MUST沿明确执行连接调用对应分支与赋值
- **AND** 未执行的分支 MUST不改变变量；后续 Get MUST读取该实例当时的值

### Requirement: 业务宿主必须显式提供上下文

每张图 MUST绑定明确的宿主合同，声明事件、输入类型、只读权限、输出和生命周期。通用事件图 MUST不内置角色、动画、关卡对象或 Gameplay 写入规则。未来宿主扩展 MUST通过同一合同提供能力，不复制画布和执行器，不自动成为全局广播订阅系统。

#### Scenario: 动画图读取宿主输入

- **WHEN** 动画宿主提供本次只读角色速度
- **THEN** 图 MUST能够通过该宿主输入执行计算
- **AND** 图 MUST不能通过 Set 修改该角色事实

#### Scenario: 图用于另一业务宿主

- **WHEN** 图需要的事件或输入不属于目标宿主合同
- **THEN** 接入 MUST明确报告缺失合同，不能按名称猜另一系统的数据

### Requirement: 变量必须有唯一声明和实例存储

变量 MUST具有稳定身份、作者名称、精确类型和初值，当前正式对象中的声明 MUST唯一来自原生图 Blackboard。显式导出的C# MUST能重建这些声明，但 MUST不成为与资产自动同步的第二份可写变量模型。每个运行实例 MUST拥有独立变量与原生节点历史，外部消费者 MUST引用同一声明和唯一布局。

#### Scenario: 重命名变量

- **WHEN** 作者重命名一个已被 Get、Set 或外部输入引用的变量
- **THEN** 名称 MUST更新而稳定身份不变，引用 MUST继续指向原变量

#### Scenario: 两个实例引用同一图

- **WHEN** 两个业务实例使用同一事件图资产
- **THEN** 一方 Set、Reset 或故障 MUST不改变另一方变量与节点历史

#### Scenario: 删除后新建同名变量

- **WHEN** 旧变量已删除且新建一个同名变量
- **THEN** 旧引用 MUST保持失效并定位来源，不能自动绑定新变量

### Requirement: 节点与类型准入必须遵从宿主合同

可创建、可连接、可导出和可执行的能力 MUST来自同一正式目录。原生节点的执行顺序、值读取时机和跨次状态 MUST保持一致。宿主不支持的节点模式、跨帧行为或副作用 MUST在正式校验中明确拒绝，不能只隐藏菜单而继续接受非法资产。

#### Scenario: 顺序执行多个分支

- **WHEN** 作者使用同次顺序执行节点
- **THEN** 系统 MUST按其原生输出顺序执行，不能改成并行操作

#### Scenario: 同步宿主接入等待节点

- **WHEN** 仅允许一次同步更新的宿主接入跨帧等待
- **THEN** 作者校验或发布 MUST报告不支持的节点和模式，不能发布部分结果

### Requirement: 宿主必须唯一拥有运行生命周期

宿主 MUST负责创建实例、绑定输入、触发事件、重置、替换和销毁。运行期间图及依赖版本 MUST与正式绑定一致。图窗口、观察界面与其它调度器 MUST不额外推进同一实例。

#### Scenario: 同一更新重复触发

- **WHEN** 同一实例收到同一次更新身份的重复推进
- **THEN** 系统 MUST拒绝重复执行并定位调度来源，不能再次累计变量

#### Scenario: 运行资产发生语义修改

- **WHEN** 作者修改正在使用的图或可达依赖
- **THEN** 旧绑定 MUST变为过期并停止作为有效发布输入，直到显式重新发布和替换
- **AND** 系统 MUST不热改原生运行对象或启用旧产物补值

### Requirement: 调用失败必须阻止结果发布

一次事件执行 MUST具有可判断的完整成功或失败结果。节点异常、非法输出和输入权限错误 MUST带实例、图、节点或字段身份报告，并阻止发布本次部分结果。编辑器与 Player 的错误捕获差异 MUST不改变这一结果。

#### Scenario: 部分赋值后发生异常

- **WHEN** 图已经执行一次 Set，随后节点失败
- **THEN** 本次调用 MUST不发布变量结果，故障实例 MUST停止被消费
- **AND** 系统 MUST不把仅恢复 Blackboard 描述为完整原生节点状态回滚

### Requirement: 人工编辑与生成必须共用正式直接API

原生UI与C#创建代码 MUST使用相同的变量声明、节点配置、端口连接、身份和局部业务规则，保留已有领域Undo和保存。调用 MUST不必经Agent Mapper、包含变量/节点/边的整图结构模型或ApplyDocument式重建中转。业务规则 MUST由所属模块承担，不新建中央Validator或整包同步事务。运行状态 MUST不能回写作者初值。

#### Scenario: C#直接配置变量与连接

- **WHEN** C#生成入口声明变量、配置节点并建立连接
- **THEN** 调用 MUST直接使用正式API并执行与人工编辑相同的类型/端口规则
- **AND** MUST不先构造另一份整图Document或JSON目标

### Requirement: 事件图必须接入公共完整代码输出

事件图 MUST向共同代码输出器提供正式对象读取和API调用输出薄适配，覆盖生成范围内的变量、节点、配置、动态端口、Macro接口、连接、布局及引用。系统 MUST复用公共export_code，不另建事件图导出器或MCP。未支持的正式内容 MUST定位对象/字段并拒绝完整导出，不能省略、占位或以半份源码替换目标。

#### Scenario: 当前图包含未支持配置

- **WHEN** 某原生节点或Macro配置不能被当前薄适配完整表达
- **THEN** 导出 MUST失败并指出精确内容
- **AND** 输入资产和原目标源码 MUST不因部分输出被改写

### Requirement: 事件图生成必须恢复身份与明确引用

公共generate_assets MUST使用指定已编译C#和正式API创建并保存明确生成范围，恢复图逻辑ID、原生Variable.ID、节点/连接/布局和共享关系。内部引用 MUST使用本次创建对象，真正范围外资源 MUST作为明确输入；MUST不以旧生成资产GUID寻找本次内部对象。Profile或owner根绑定 MUST按指定上下文显式恢复，不全局扫描猜测。

#### Scenario: 删除旧生成范围后重新生成

- **WHEN** 旧生成图及内部对象已不存在，但源码和正式外部输入仍在
- **THEN** 生成 MUST恢复等价变量、节点、接口、连接与布局，并恢复指定根引用
- **AND** 现有Pose Get MUST能按同一逻辑图与变量身份重新解析

### Requirement: 导出和生成必须保持显式非同步语义

人工编辑和保存事件图 MUST不自动导出或改写C#。只有明确export_code才输出当前完整结构；明确generate_assets MUST按指定已编译代码重建范围，不自动合并未导出的人工修改。两个作者工具 MUST不自动Build/Play，不建立源码解析同步、操作日志或整包reconcile。

#### Scenario: 人工修改后未导出就生成

- **WHEN** 当前资产有未导出的人工修改而调用方明确执行指定代码生成
- **THEN** 生成内容 MUST以指定代码为准
- **AND** MUST不将人工修改反推至源码、隐式合并或创建同步状态
