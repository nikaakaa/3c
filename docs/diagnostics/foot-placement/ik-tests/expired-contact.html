这个测试要证明什么

接触还在继续时，旧目标必须保留；进入下一次摆腿后，CurrentContact 里记住的旧事件不能继续占用脚的目标。否则，即使下一步地面路径已接受，系统仍会依赖“当前脚底有命中”；脚在空中、探针暂时没有命中时，最终 IK 位置权重就会掉到 0。

本次修正让目标的有效期同时依赖实际 Contact > 0。它没有增加一条手绘权重曲线，也没有改变作者提供的 IK 权重。

输入来源、未采样字段与边界
  • 保留原始帧间隔、正式接触/锁定参数、事件序号与周期、已完成的落点预测、地面路径顶点/接触/覆盖面，以及每帧 23 个脚底采样点。输入文件保留源 CSV 的 SHA-256。
  • 先在 GameplayLabFixed 当前地形上重新查询原始脚底点，逐点核对命中、位置和法线；不匹配即失败。候选输出姿态另做真实地形查询，不复用旧姿态的命中。最终输出再次检查脚底点，命中地面时允许的浮点误差为 0.2 mm；没有查询命中不表示已经证明空间无碰撞。
  • 起点用首帧已记录的最后落点、下一落点、已释放事件初始化；窗口前的插值历史没有完整记录，两版统一重新建立。历史重算要求权重与原采样完全相符，不要求全部空间输出逐位复现。
  • 原 clip 的绝对 normalizedTime 未采样，以 0 构造事件；实际事件身份由已记录的序号、周期、来源与左右脚绑定后逐帧校验。此调用链只消费事件身份与已记录的剩余时间。事件 SwingProgress 用路径 progress 填充，仅用于有限值合法性检查，不驱动本实验的运动计算。
  • 采样里的 hip/knee 是骨盆修正后、腿部求解前的位置，实验转换回世界坐标；本窗口不创建接触锚点，不评估 Landing 可达性、骨盆或膝盖。ToeRotation 未采样，本链不消费，构造为单位四元数。来源连续性用这段采样共同的动画来源标识。
  • 这是单脚函数场景回归，不执行 KCC、动画状态机、完整预测器、双脚骨盆或最终腿部 IK。Landing / Releasing 伸直和水平冻结问题不在这次修正范围。
