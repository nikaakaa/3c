## Context

动机见 proposal.md，源码证据见 audit.md。全项目候选扫描不等于全路径运行测量；新建 struct、构造期集合、异常字符串和vendor未使用源码不计作已证明的每帧GC问题。当前确定的主问题是周期入口重新创建运行装配、工作存储和输出副本。

正式约束：Session 唯一驱动；角色/世界同一事务提交；技能编译运行，Pose 原生实例求值；Timeline 自己管理播放私有状态；输出可能被网络、回滚、表现和诊断跨帧持有。不能通过共享可写状态消除分配。

## Goals / Non-Goals

**Goals:**

- 正式准备完成后，声明容量内的正常运行在项目及其正式依赖调用链产生 0 托管分配，包括多步、回滚重放、技能切换、收发包和所选正式诊断模式。
- 通过现有owner准备、复用和释放存储，保持原参数、数值顺序、求值次数/顺序、状态隔离、协议和输出生命周期。
- 分别报告初次/峰值/稳态分配、线程与场景；有未覆盖第三方或服务端路径时不能给全项目通过结论。

**Non-Goals:**

- 不以全局禁用GC、主动GC.Collect、关诊断/网络/IK或无限堆容量替代治理。
- 不同时增加脏标记缓存、公共子表达式合并、短路修复、Pose IR或第二Timeline运行器；这些会改变语义或工作量，另行明确。
- 不把 Editor 导入、离线生成和进程启动全部强制变成无分配；这些阶段仍有明确内存释放与报告边界，不能在战斗中冒用阶段豁免。

## Decisions

### 1. 按现有owner准备存储，不建立全局池

输入是正式内容、roster、能力安装、最大活动播放/效果、回滚窗口和消息上限；输出是对应 Session/Actor/领域实例持有的工作容量。容量优先从已发布布局推导，无法推导的动态上限进入所属领域正式配置，准备阶段检查一致性。数值在具体内容上计算，不在文档中猜默认数值。

| 同级方案 | 业务收益 | 成本与选择 |
| --- | --- | --- |
| owner长期持有固定存储 | 每次角色推进无需重建装配，职责清楚 | 占用按峰值准备的内存；用于固定roster和可推导技能工作集 |
| 领域内部有界租用 | 支持同时存活的消息、快照、结果 | 需要精确退还时机和代次；用于跨帧或异步结果 |

两种方式按寿命使用，不叠一个万能池。Immutable content/layout继续共享；frame/tick/input等可变上下文沿原接口重绑定，退出时清引用，避免存活对象钉住资源。

### 2. 事务复用必须保留Pending与Committed隔离

G01–G04中的new和Clone要沿完整Evaluate→World→Finalize→Commit/Discard处理。先保留现有算法，以预分配状态页/工作页替换反复分配；snapshot和历史结果有自己的保留槽，不引用下一步会覆盖的临时集合。

| 同级方案 | 业务收益 | 成本与选择 |
| --- | --- | --- |
| 固定容量完整状态复制 | 易于保持当前原子提交与失败回退语义 | 仍有复制CPU成本；作为首次治理的默认实现方向 |
| 分页写时复制或增量日志 | 大状态少量写时减少复制 | 改变状态存储和恢复复杂度；只有已有正式机制可直接复用或独立证据支持时再定，不夹带到本次第一步 |

结果在所有消费者完成前不可回收。租用标识包含owner、槽和代次；释放沿已有完成/丢弃/超窗边界，双释放和使用过期结果明确失败。保存点嵌套使用预留层级，不偷用单个scratch覆盖外层状态。

### 3. 各领域独立治理，不改已有业务算法

| 模块 | 输入 | 处理 | 输出/释放 |
| --- | --- | --- | --- |
| Skill/Control/GE/Equipment | 当前输入、状态和正式布局 | 固定执行装配，复用值输入栈、集合、journal与scope；字符串身份在准备期解析 | Pending结果在提交/丢弃后按消费者寿命归还 |
| Timeline/EventGraphs | 内容、播放身份、前后时间与调用上下文 | 每播放槽与事务槽保存工作数据，快照写入正式历史存储；事件图只更换分配型scratch | 保持Marker、停止、回滚及事件唯一身份，不改变触发次数 |
| Pose/Blend/Foot/IK | committed事实、正式图、rig和容量 | G07改为节点/实例持有请求和去重存储，查询/姿态/Goal缓冲按既有owner持有；检查delegate/装箱 | 唯一Barrier与Seal完成前禁止回收姿态；不改IK公式与求值顺序 |
| Camera/Input/AI | 镜头输入、目标、角色观测 | 复用目标/请求/输入批，按实际任务检查插件节点；保留单一输入来源 | frame借用只在同步消费者内有效，跨步输入进入正式历史槽 |
| World/KCC/DotRecast | roster、运动批与solver状态 | 固定接触、路径和批结果存储，保留碰撞排序与求解公式 | solver候选与角色状态同一事务接受或丢弃 |
| 网络/服务端 | 收包、编码对象、可靠事件、重传窗口 | writer写入拥有容量的buffer；传输层发送完成才释放；服务端按Scene/Room归属 | 不改变canonical bytes、协议版本含义、可靠性或回滚历史 |
| UI/资源/Rendering | 真实状态变化与资源事件 | 避免每次getter复制历史；更新复用文本/视图；事件对象/特效在正式准备池租用 | 生命周期退出解除订阅、释放资源；不为GC把材质或native泄漏藏起来 |
| Diagnostics/Performance | 已提交事实、采样兴趣、固定记录容量 | typed记录写有界存储，格式化在明确导出阶段；采样期间后台同样计分配 | 慢消费者有正式容量失败，不静默丢权威事实或伪造完整采样 |

第三方若无可用无分配API：记录具体调用栈与版本，对已有插件源码/API修正和调用形态调整列业务取舍；不能未经证据替换整个插件或宣称项目侧零分配即整体达标。Fantasy消息释放沿其正式生命周期，不能在异步发送仍使用payload时复用数组。

### 4. 借用视图与租用结果分开

同步、无逃逸消费者使用明确count的借用视图；跨帧、异步、history消费者使用领域拥有的租用存储。Span不能跨await或落入持久字段。原来返回独立List/byte[]的公共调用必须与所有消费者一起迁移，不能偷偷改成返回下一帧会变的同一个List。

借用减少管理成本但不允许保留；租用支持网络和回滚但需要释放合同。根据真实消费寿命选择，不能为了减少代码统一成不安全借用或全都复制。

### 5. 容量不足是正式失败，不是在热点扩容

最大并发技能、效果、Timeline、姿态源、碰撞候选、网络在途包、回滚步和诊断记录进入对应正式容量来源。内容可证明超限则准备失败；运行达到无法接受的新请求时走原领域拒绝/背压或事务失败，不部分发布、不丢权威事件、不悄悄扩容。容量增长只能在明确退出Active后的正式重准备中执行。

预留峰值带来常驻内存开销；更紧容量降低内存但更早触发准入失败。报告当前内容所需下界、配置值与峰值占用，由业务场景约束选择，不替用户用硬编码上限缩减战斗能力。

### 6. 性能证据沿唯一正式工作流

复用 ThirdPersonPerformanceCaptureWorkflow 的 Request→Smoke→Replay→Capture 和现有 GC Allocated In Frame 指标。指标缺失或不支持为Unavailable，不能显示0。审查现有计数器覆盖线程，服务端独立进程使用同一Run关联的分配证据，不能用客户端主线程代表服务器/后台线程。

场景覆盖：Local Fixed/Float32、支持的回滚与权威模式、移动/楼梯/连续攻击闪避、首次技能切换、多个Actor、回滚峰值、收发可靠消息、UI/特效、诊断开/关与生命周期进出。每条场景保留产品/内容身份、线程、预热和计量窗口、调用栈、总分配字节、非零帧、峰值、GC次数/停顿与常驻内存。计量区间内不能通过热身把真实首次技能路径藏掉，首次内容使用单列并纳入运行约束。

采样器与格式化落盘独立归因；运行窗口中的后台分配仍计入，只有明确窗口结束后的导出不计常态。没有匹配Player与正式Gate，本轮不旁路搭建采样器，因此 audit.md 只给源码结论。

## Risks / Trade-offs

- 提前复用结果污染回滚/表现 → 按全部消费者完成与generation归还，保留提交隔离。
- 池持有资源造成常驻内存升高 → 记录容量占用与退出释放，不只看GC Alloc。
- 诊断关闭后看似达标 → 正式诊断模式单独计量，保留trace业务与异常定位。
- string/接口foreach/委托/异步隐藏分配 → 沿实际生成调用核对，不按关键词直接改掉正确代码。
- 多任务正在修改同一文件 → 本次只写文档，实施遇到冲突明确抛出；不另建兼容路径或回退正确修改。
- snapshot/protocol依赖不可变结果 → 迁移所有权不改变数据身份和协议bytes，不能用裸引用替换承诺独立寿命的结果。

## Migration Plan

1. 在既有领域准备入口确定内容推导容量与owner寿命；各切片记录基线与涉及消费者。
2. 按模拟/状态、Timeline、表现、网络/世界、UI/资源/诊断等独立业务切片迁移，不把顺序当成收益排序；跨域共同结果合同先由唯一owner定义。
3. 每切片同步生产者、全部消费者、必要正式配置和旧分配入口删除，中文小步提交。失败保留证据，只撤销本切片且不覆盖其它正确修改。
4. 正式性能证据随既有workflow发布；不新增测试代码或手动验证task，不宣称未覆盖模块已完成。
