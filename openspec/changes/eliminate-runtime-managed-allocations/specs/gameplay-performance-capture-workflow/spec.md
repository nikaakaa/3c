## ADDED Requirements

### Requirement: 零分配结论必须具备完整场景与线程归因

正式性能工作流 MUST 沿已有Request、Gate、采集与原子产物入口记录分配证据，包含精确产品/内容/场景身份、首次使用、峰值与稳态区间、运行线程范围、总分配字节、非零帧、峰值和GC回收停顿。客户端、后台线程和服务端证据 MUST 明确区分；未测、计数器不支持或记录溢出 MUST 标记Unavailable或失败，不填零。MUST 不创建第二采集驱动或私有模拟循环。

#### Scenario: 只有源码扫描

- **WHEN** 报告仅有new、ToArray或构造器调用证据
- **THEN** MUST 标记静态候选或已确认分配调用，不给未测bytes/frame和全项目通过结论
- **AND** 构造期、周期调用、诊断分支和不可达第三方 MUST 分开

#### Scenario: 诊断开启场景

- **WHEN** 正式场景启用诊断或值采样
- **THEN** MUST 记录采样自身分配及线程范围，运行窗口中的格式化/后台分配不能隐藏
- **AND** 明确窗口结束后的导出分配 MUST 单列，不能误算为每帧游戏分配

#### Scenario: 历史采集不匹配当前源码

- **WHEN** 现有结果的产品或内容身份与候选不同
- **THEN** MUST 只把它作为历史证据，不作为当前0 GC结论
- **AND** 缺少合法Gate时 MUST 保持原工作流拒绝行为，不旁路采样
