# 脚部几何检测检查报告

本轮只检查源码、正式配置、现有手动采样和场景预制体，没有修改运行代码、停止 Play、重新烘焙或运行 replay。上一轮候选 `2f59a39f8` 尚未撤销；它的撤销应与后续实施明确处理。

## 结论

已确认球形扫掠在台阶棱边命中后，会把侧向接触产生的倾斜法线作为坡面法线接受，并可能选择高台阶作为整脚的当前支撑。现有采样显示探针中心仍位于低踏面范围，旁边高台阶的棱边就能通过半径 8 厘米的球进入候选。这能解释边缘位置支撑目标跳一级的条件；还不能据此断言所有悬脚和最终骨骼抖动只有这一个原因。

没有证据说明这段问题是查询距离不够、容量溢出或台阶之间存在空洞。不能把球的擦边命中本身判作物理引擎错误；需要检查的是业务把该碰撞当作落脚支撑是否合理。

## 代码中可以确定的不足

1. 球形查询的坡度过滤使用碰撞返回法线，未进一步核对真实踏面是否位于脚底有效覆盖范围内；棱边接触法线也能通过过滤。
2. 每个探针先把多个命中缩成最近的一个，后续 Heel/Toe 合并没有完整候选可用；取更大竖直修正不能区分稳定承重与旁侧擦边。
3. 同一个 Collider 的身份不等于同一踏面身份；查询当前只保留 Collider ID、命中点及法线，没有将真实面覆盖作为落脚选择条件。
4. 预测路径的位置可以来自低处落点，但当前 `SwingGround` 的法线和 SurfaceIdentity 来自当前支撑查询。棱边探针改变的法线可能进入修正方向，位置和法线不是同一处支撑事实。
5. 五点校准显示与当前两球运行检测不一致；半径也与未来落点查询耦合。当前双探针中心间距在普通移动采样中约 7.07–8.11 cm，球直径为 16 cm；这只能说明探测覆盖明显超过两中心线，不能在没有鞋网格覆盖对照时断言球一定过大。
