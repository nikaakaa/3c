## 剩余可定位问题

### Eye 缺少直接消费的输入

`Generated/Character/Eye/OriginalStage480.hlsl`：

- 行 675 起消费 `_SceneFogParamsPart1/2/3`。
- 行 809–813 消费 `_SceneWeatherParamsPart1[2][3]`。该值作为饱和度混合因子：零会选择亮度灰度，一会保留原颜色。
- 同一阶段还采样 `_InternalLut_Char`。

当前 `CorinRestoredRenderProfile.ApplyGlobals` 没有提供天气与雾矩阵；LUT 纹理只在后面的 `CharacterCompositePass` 绑定，而 Eye 在更早的 `CharacterBufferPass` 绘制。需要验证首帧绑定值和绘制顺序。源代码直接证明缺失发布入口，尚未取得本轮 Eye 像素的 GPU 常量读回，不能宣称这是全部眼部异常的唯一根因。

此饱和度运算同时由 `20260905_corin_eye_shader_typed_v3/entry480.original.asm` 尾部证实：比较 `cb0[56].z < 0.999`，按 `(0.212673,0.715152,0.072175)` 计算灰度，然后以 `cb0[56].z` 对灰度和原色插值。不是仅凭恢复 HLSL 猜测用途。

### MatCap 参数数组的重新加载入口缺失

`CorinRestoredMaterialSet.ApplyRuntimeArrays` 构造四组五元素向量数组。目前调用者只有 `Initialize` 与 Editor 的 `RebuildOriginalModelPrefab`；Runtime 的材质集合加载和 Renderer Feature 初始化没有调用它。必须检查 Domain Reload/重新加载后的 `Material.GetVectorArray` 长度和值，确认是否为零；源纹理字节一致不能代替参数数组有效性。

### 原描边尚缺自己的完整输入与实际绘制验证

`CharacterOutlineDeferred` 和 `FaceOutlineDeferred` 均有恢复源码，但当前未调度。它们读取的 `_PostOutlineTint`、`_NonJitteredProjMatrix` 等也未被当前 Profile 完整发布。应先恢复输入及顺序，再独立验证，不能仅增加 DrawRenderers 后即宣布闭合。
