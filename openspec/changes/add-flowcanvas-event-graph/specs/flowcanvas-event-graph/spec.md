## Purpose

定义以事件为入口、由原生可视化节点完成计算、判断、变量读写与操作调用的通用事件图能力。各业务系统提供自己的事件、数据和生命周期，实例独立运行，共享作者与节点机制，不要求所有系统进入一张全局图。

## ADDED Requirements

### Requirement: 事件图必须复用原生作者和执行语义

系统 MUST允许作者使用原生画布、事件、执行连接、变量、计算、条件和 Macro 构建事件逻辑。事件图 MUST直接采用已准入原生节点的执行语义，不要求作者把同一逻辑另行编译为项目专用事件程序，不在不支持时切换另一执行方式。

#### Scenario: 作者连接条件和赋值

- **WHEN** 作者连接更新事件、条件分支和变量赋值
- **THEN** 事件发生时 MUST沿明确执行连接调用对应分支与赋值
- **AND** 未执行的分支 MUST不改变变量；后续 Get MUST读取该实例当时的值

### Requirement: 业务宿主必须显式提供上下文

每张图 MUST绑定明确的宿主合同，声明事件、输入类型、只读权限、输出和生命周期。通用事件图 MUST不内置角色、动画、关卡对象或 Gameplay 写入规则。未来宿主扩展 MUST通过同一合同提供能力，不复制画布和执行器，不自动成为全局广播订阅系统。

#### Scenario: 动画图读取宿主输入

- **WHEN** 动画宿主提供本次只读角色速度
- **THEN** 图 MUST能够通过该宿主输入执行计算
- **AND** 图 MUST不能通过 Set 修改该角色事实

#### Scenario: 图用于另一业务宿主

- **WHEN** 图需要的事件或输入不属于目标宿主合同
- **THEN** 接入 MUST明确报告缺失合同，不能按名称猜另一系统的数据

### Requirement: 变量必须有唯一声明和实例存储

变量 MUST具有稳定身份、作者名称、精确类型和初值，声明由原生图 Blackboard 唯一拥有。每个运行实例 MUST拥有独立的可变变量和原生节点历史。外部消费者 MUST引用同一声明，不能创建第二份可写变量镜像。

#### Scenario: 重命名变量

- **WHEN** 作者重命名一个已被 Get、Set 或外部输入引用的变量
- **THEN** 名称 MUST更新而稳定身份不变，引用 MUST继续指向原变量

#### Scenario: 两个实例引用同一图

- **WHEN** 两个业务实例使用同一事件图资产
- **THEN** 一方 Set、Reset 或故障 MUST不改变另一方变量与节点历史

#### Scenario: 删除后新建同名变量

- **WHEN** 旧变量已删除且新建一个同名变量
- **THEN** 旧引用 MUST保持失效并定位来源，不能自动绑定新变量

### Requirement: 节点与类型准入必须遵从宿主合同

可创建、可连接、可导出和可执行的能力 MUST来自同一正式目录。原生节点的执行顺序、值读取时机和跨次状态 MUST保持一致。宿主不支持的节点模式、跨帧行为或副作用 MUST在正式校验中明确拒绝，不能只隐藏菜单而继续接受非法资产。

#### Scenario: 顺序执行多个分支

- **WHEN** 作者使用同次顺序执行节点
- **THEN** 系统 MUST按其原生输出顺序执行，不能改成并行操作

#### Scenario: 同步宿主接入等待节点

- **WHEN** 仅允许一次同步更新的宿主接入跨帧等待
- **THEN** 作者校验或发布 MUST报告不支持的节点和模式，不能发布部分结果

### Requirement: 宿主必须唯一拥有运行生命周期

宿主 MUST负责创建实例、绑定输入、触发事件、重置、替换和销毁。运行期间图及依赖版本 MUST与正式绑定一致。图窗口、观察界面与其它调度器 MUST不额外推进同一实例。

#### Scenario: 同一更新重复触发

- **WHEN** 同一实例收到同一次更新身份的重复推进
- **THEN** 系统 MUST拒绝重复执行并定位调度来源，不能再次累计变量

#### Scenario: 运行资产发生语义修改

- **WHEN** 作者修改正在使用的图或可达依赖
- **THEN** 旧绑定 MUST变为过期并停止作为有效发布输入，直到显式重新发布和替换
- **AND** 系统 MUST不热改原生运行对象或启用旧产物补值

### Requirement: 调用失败必须阻止结果发布

一次事件执行 MUST具有可判断的完整成功或失败结果。节点异常、非法输出和输入权限错误 MUST带实例、图、节点或字段身份报告，并阻止发布本次部分结果。编辑器与 Player 的错误捕获差异 MUST不改变这一结果。

#### Scenario: 部分赋值后发生异常

- **WHEN** 图已经执行一次 Set，随后节点失败
- **THEN** 本次调用 MUST不发布变量结果，故障实例 MUST停止被消费
- **AND** 系统 MUST不把仅恢复 Blackboard 描述为完整原生节点状态回滚

### Requirement: 作者修改必须进入统一资产事务

原生编辑与 Document 修改 MUST使用相同能力、类型、变量引用和资产约束，并进入唯一 Mutation 与保存事务。运行时状态和观察值 MUST不能回写作者初值或图拓扑。

#### Scenario: Document 修改变量类型

- **WHEN** 作者通过 Document 修改变量类型且现有连接不匹配
- **THEN** 事务 MUST拒绝并定位变量与连接，不保存部分修改
