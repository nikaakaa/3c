## Purpose

定义角色动画图中通用骨骼变换的输入、模式、参考空间、后代传播和输出行为，使作者能够用同一能力组合侧倾、俯仰和骨骼偏移，并保持现有动画、约束求解和最终骨骼输出的一致性。

## ADDED Requirements

### Requirement: 骨骼变换必须是可组合的通用姿势能力

系统 MUST允许作者对输入姿势中的一个明确物理骨骼施加位置、旋转、缩放变换并输出新的姿势。能力 MUST不包含角色名、跑步、侧倾、攻击或其它业务特判。多个骨骼修改 MUST能够通过现有图连接按明确顺序组合；虚拟骨骼 MUST不作为直接修改目标。

#### Scenario: 同一能力用于不同角色效果
- **WHEN** 作者分别为身体侧倾和头部转向配置骨骼变换
- **THEN** 两者 MUST使用同一通用能力，仅由输入参数、目标骨骼和图拓扑区分
- **AND** MUST不要求新增对应业务专用节点

### Requirement: 动态变换必须保留精确类型与明确来源

位置和缩放 MUST支持 Vector3，旋转 MUST支持 Quaternion，权重 MUST为 [0,1] 内的有限浮点值。每个有效变换通道 MUST由作者明确选择常量或动态端口；动态来源缺失、类型错误或跨帧输入 MUST报出对应图、节点和端口，不得回退常量、单位值或上一帧。旋转常量的欧拉角编辑 MUST形成相同旋转语义，不创建第二份运行旋转真相。

#### Scenario: 同一节点连续接收不同旋转
- **WHEN** 两个合法帧分别给同一骨骼变换传入不同 Quaternion
- **THEN** 每帧 MUST使用本帧旋转和本帧输入姿势形成结果
- **AND** MUST不累加上一次输出或要求修改作者资产

#### Scenario: 作者选择动态位置却没有连接
- **WHEN** 一个启用的位置通道声明动态来源但端口没有生产者
- **THEN** 作者或实例绑定校验 MUST拒绝该节点并定位缺失端口
- **AND** MUST不隐式改用静态位置

### Requirement: 各通道必须明确忽略叠加与替换

位置、旋转和缩放 MUST各自支持 Ignore、Add、Replace。Ignore MUST保留输入；Add MUST分别表示位置偏移相加、所选参考空间中的增量旋转左乘和缩放倍率逐轴相乘；Replace MUST表示目标值替换。系统 MUST在所选参考空间形成目标，再用权重从原值插值；旋转 MUST使用最短弧插值。非法变换 MUST进入正式失败流程，不输出半份姿势。

#### Scenario: 权重为零和完整权重
- **WHEN** 同一输入以权重 0 或 1 求值
- **THEN** 权重 0 的结果 MUST保留完整输入姿势，权重 1 MUST应用全部有效通道目标
- **AND** 未启用通道 MUST不发生变化

#### Scenario: 旋转叠加不替换当前跑步姿势
- **WHEN** 一个旋转通道选择 Add 并输入侧向旋转
- **THEN** 结果 MUST保留当前动画旋转并叠加该增量
- **AND** MUST不把当前动作替换为固定旋转姿势

### Requirement: 参考空间必须具有一致的业务含义

系统 MUST提供父骨骼局部空间与角色组件空间。父局部空间 MUST表示目标相对父骨骼的 TRS，根骨骼以组件基准为父；组件空间 MUST表示相对角色组件的 TRS。位置、旋转、缩放 MUST使用同一选定空间解释，参考变换 MUST来自本次输入姿势。所选空间 MUST不隐式依赖场景 Transform 或相机朝向。

#### Scenario: 父骨骼已经旋转
- **WHEN** 父骨骼在输入姿势中有旋转，作者分别在父局部与组件空间施加相同数值偏移
- **THEN** 两份结果 MUST分别沿父骨骼基准和角色组件基准解释该偏移
- **AND** 输出 MUST仍可由下游按明确姿势空间消费

### Requirement: 子骨骼传播必须可显式选择且保持姿势一致

传播开启时，系统 MUST保留输入姿势中各后代的局部 TRS，并让它们随修改后的父链重建组件空间结果；传播关闭时，后代物理骨骼的组件空间姿势 MUST保持输入值。无关骨骼 MUST保持不变。受影响虚拟骨骼 MUST按现有派生规则与修改后的物理姿势保持一致。

#### Scenario: 身体骨骼倾斜并传播
- **WHEN** 作者旋转身体骨骼且开启子骨骼传播
- **THEN** 其后代的位置与旋转 MUST随父链改变，后代局部姿势保持输入关系
- **AND** MUST不出现父骨骼已经倾斜而后代仍留在原组件空间位置的结果

#### Scenario: 保持后代组件空间姿势
- **WHEN** 作者关闭传播并修改目标骨骼
- **THEN** 目标 MUST按配置变化，后代物理骨骼的组件空间姿势 MUST保持输入值
- **AND** 后续空间转换 MUST反映相应局部补偿

### Requirement: 骨骼变换必须遵守正式姿势帧与资源生命周期

输入姿势 MUST只读，修改结果 MUST由节点所属实例的输出承载。同帧重复读取 MUST得到相同已完成结果，不重复修改或推进任何历史；不同角色和不同调用实例 MUST隔离。正常逐帧执行 MUST不产生托管内存分配。无姿势输入 MUST保留正式无姿势语义，不伪造参考姿势。重置、丢弃、故障及释放 MUST沿用现有帧规则，最终可见骨骼写入 MUST仍由唯一正式输出完成。

#### Scenario: 同一输入连接两个修改分支
- **WHEN** 两个骨骼变换节点读取相同输入并使用不同参数
- **THEN** 两个结果 MUST独立，原输入和另一分支 MUST不被覆盖
- **AND** 观察节点 MUST不造成额外修改或分配新的逐帧对象

#### Scenario: 本次姿势失败
- **WHEN** 动态输入或姿势求值在本次帧失败
- **THEN** 系统 MUST按现有阶段规则丢弃或故障，不发布部分骨骼
- **AND** MUST不通过图外 Transform 修改补偿失败

### Requirement: 人工与代码作者必须使用同一变换合同

节点详情、typed 端口、正式作者修改、Undo、内容版本及 C# 作者入口 MUST表达同一组变换模式、空间、来源、权重和传播规则。被替代的旧字段 MUST完成清理，不保留运行兼容路径。迁移已有使用点时，任何与已确认正确行为冲突的语义差异 MUST明确报告，不能静默改变。

#### Scenario: 导出并重新生成骨骼变换
- **WHEN** 作者通过正式入口导出并重新生成配置过的节点
- **THEN** 目标骨骼、通道模式、动态连接、空间和传播行为 MUST保持一致
- **AND** MUST不需要独立骨骼编辑窗口或旧文档协议

### Requirement: 普通骨骼变换子图必须可以重复调用

同一资产目录中的普通 Subgraph MUST允许被多个 PoseSubgraph 节点调用，每个调用 MUST使用当前 Native Handler 独占的子实例和缓冲。作者校验 MUST区分资产所有者与调用引用数量；根图、状态子图和 Control Rig 的既有独占约束 MUST保持不变，不允许把状态所有权和普通调用混在同一子图上。

#### Scenario: 起步与循环复用同一骨骼变换
- **WHEN** Run Start 和 Run Loop 各调用同一个普通骨骼变换子图
- **THEN** 作者校验 MUST接受这两个调用，并继续检查接口和循环依赖
- **AND** 两次调用 MUST具有独立实例和输出缓冲，状态过渡时不得覆盖彼此结果
