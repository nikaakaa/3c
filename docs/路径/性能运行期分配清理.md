# 性能运行期分配清理

固定输入经过 `FixedCharacterEvaluationRuntime.Evaluate` 生成角色逻辑结果，技能 Timeline 请求进入 `CharacterTimelineHost`，再由逻辑提交和表现提交分别持有播放状态。性能采样确认 Timeline 启动阶段会创建播放对象、六组片段列表、比较器和两块评估存储。

当前 `TimelineRuntimeService` 按内容版本和播放模式维护已释放播放器。只有 `CharacterTimelineHost.ReleaseConfirmedPlaybacks` 同时确认逻辑所有者已释放、表现播放已结束且确认 Tick 已通过后，才调用 `ReleasePlayback` 将对象放回对应池；下一次同内容同模式的请求重置句柄、代次、游标、状态和请求列表后复用。评估存储继续归播放器持有，避免改变已提交评估的所有权。

角色事实、表现命令和 Trace 在 `FixedCharacterEvaluationResult.TakeOutputs` 后交给 `SimulationActorTickResult`。`FixedCharacterTraceSink` 在每次求值开始时绑定当前输出 bank，避免切换 bank 后把新 Tick 的 Trace 写入旧结果。完成 Tick 的外层产品槽在下一次外层事务开始时调用归还合同，Actor 将已消费的输出 bank 清空后放回池；Finalize 在结果构造或入槽失败时也会立即归还已转移的 bank。求值结果、Finalize、回滚提交和表现消费者在此之前仍共享同一份 bank。状态快照仍由完成 Tick 持有，未把它改成会被下一 Tick 覆写的共享状态。

`FixedCharacterRuntimeStateTransaction.Snapshot → FixedCharacterRuntimeState.AdoptSnapshot` 原本就通过数组重载直接持有 abilities、action 和 input 数组；此前“消除数组二次复制”的判断错误。本轮删除误加的 `ownsCollections` 重载和已无调用的集合复制构造器，恢复唯一的数组所有权入口，避免重复排序和校验。Timeline 只读集合也通过明确类型直接传递。旧 Tick 仍持有独立状态，下一 Tick 复用事务工作区，不覆写历史状态的数据。

`FixedAbilityFinalizePass.Execute → FixedCharacterEvaluationResult.Consume → FixedCharacterRuntimeState.WithTimelineOutputs` 现在把全部推进、停止和无所有者终态清理放进 Actor 求值结果持有的复用列表，再一次生成最终 Timeline 集合和状态。原先每个推进请求、每个实际删除和终态清理都会创建中间列表、列表副本、只读包装和状态。现在仍按原顺序先提交全部请求、再采集推进快照、再删除停止句柄；同句柄快照仍先移除再追加，保留旧代码的列表顺序和哈希输入。Completed / Stopped 仍只在关联 Action 活跃且执行代次一致时保留。最终非空快照使用独立数组和只读包装，列表工作区在消费或丢弃后清空。

`FixedAbilityFinalizePass.Execute → FixedCharacterRuntimeStateCodec.ComputeHash → WriteValues / WriteAbilityExecutionState / WriteMotionWarpStates` 复用线程内的槽位键和执行帧排序列表，槽位按编号、执行帧按 Action instance 编号编码。字典使用具体类型的结构体枚举器，避免从 `IReadOnlyDictionary.Keys` 取得枚举器。角色分区、恢复用 Timeline 快照和执行帧排序使用共享 `IComparer`。共享的 `GameplayAbilityExecutionFrame` 改用 `Dictionary` 保存值，克隆时直接复制字典；Fixed 和 Float32 的编码器继续负责排序，运行逻辑依然按槽位读取和写入。

`SimulationGameplayEffectState.Freeze / Commit → GameplayEffectStateAggregate → FixedCharacterRuntimeStateCodec.WriteCanonical → GameplayEffectStateAggregateCodec.Write` 的已提交 GE 数据改为规范排序的数组：Tag source、属性、周期、预测 Journal 和生命周期版本只保存一份正式数据，字符串键按 Ordinal、编号键按数值排序。哈希与状态写出通过轻量 `ReadOnlySpan` 视图直接读取，不再创建六组集合，也不再复制属性、Modifier、活动 Effect 和预测记录。可写事务仍拥有自己的工作集合，恢复时通过既有分组复制入口取得可写副本；不同 Tick 共享没有变化的数组和值对象，变化项仍由新快照独立持有。

GE Spec 的参数与捕获属性、共享预测记录的属性改用 `SortedList`，保留 Ordinal 顺序并提供索引访问。Fixed 预测完成、预测回滚、Additional Effect 和编码沿同一数据源按索引读取，不再复制一遍预测属性键，已无调用的 `PredictionAttributes` 工作区和聚合 `CopyTo` 入口删除。字符串数组直接写出，Cue 使用线程内复用列表排序，消除 `ToArray / OrderBy`。可写事务已经计算各映射的 dirty 标记，变化快照生成直接依赖这些标记，不再次扫描整张映射；未变化的单项仍按内容共享。二进制字段、长度前缀、规范顺序与版本标识保持原合同，运行中行为等价未验证。

`ActionAdmissionControl.Evaluate` 现在沿 `FixedActionRuntime / Float32ActionRuntime → IActionAdmissionReadPort → ActionAdmissionControl` 直接消费 `IReadOnlyList<string>`。Fixed / Float32 GE 查询端口、Action 标签写入端口和装备标签端口均保留同一列表数据源，去掉 `IEnumerable` 的接口枚举器。Tag 祖先不再在首次准入时创建 `List<string>`、数组并缓存；每次判断沿已安装目录的父链索引加入当前工作 `HashSet`，仍按原顺序支持 Required、Block、Cancel 和动作标签祖先匹配。初始化 Tag 目录也直接作为列表传给状态事务，避免额外列表复制。

当前还不能视为 0 GC：

- `Snapshot / FixedSkillExecutionState.TakeSnapshot` 仍生成完成 Tick 的状态对象，变化的技能字典、能力数组、Action / Input 数组和执行帧克隆仍有分配。
- `TimelineRuntimePlaybackSnapshot / CharacterTimelineSnapshotCodec.Capture` 仍复制活动片段、TreeDecision 和 TreeClip 数据；批量提交最终非空 Timeline 集合仍创建数组、只读包装和一份状态对象。
- GE 在 `Freeze / CreateChangedFrom` 生成变化快照、创建 Effect / Spec / 预测记录和恢复可写事务时仍有分配；可写工作集合已经改为按 Ordinal／数值顺序维护的 `SortedList` 并用索引遍历，新增节点的移动成本和容量增长仍需后续处理。`SortedList` 的键值视图首次访问也可能分配。
- `TimelineRuntimeService.TryCreateTimelineRequest` 仍格式化 `timeline:{handle}`，`TimelineRuntimeCallBindingSource.TryCreateExecutionIdentity` 仍拼接调用身份字符串。
- 工作列表和线程内编码工作区首次使用或容量增长仍可能分配。最终状态和嵌套快照的回收必须覆盖历史 Tick、回滚和表现消费者的留存期，不能直接交给下一 Tick 清空。
